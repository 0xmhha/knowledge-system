# 마스터 작업계획 — coding-agent · CKS(ckg/ckv) 시니어-전문가 모방 시스템

> 목적: 지금까지 합의한 "작업해야 할 모든 것"을 한 문서로 통합. 이후 작업의 단일 기준.
> 작성일: 2026-06-26. 이 문서가 `07`의 평면 리스트를 **수직완결 프레임으로 재편**함(`07`~`11`은 항목별 상세계약으로 유효).

---

## 0. 원칙 (이 문서를 관통)

1. **수직완결 우선** — "갭을 넓게 메우기"가 아니라 **한 워크플로를 끝까지 제대로 동작**시키기. 지금은 모든 게 부분구현이라 *하나도 제대로 안 돈다.* 가장 완성에 가까운 것부터 완결.
2. **우선순위**: 버그수정 → 코드리뷰 → (보류) 신규기능. 신규기능은 앞 둘의 깊은 분석에 의존하므로 뒤로.
3. **모듈화·재사용을 시작부터** — 각 능력은 *데이터를 가진 가장 낮은 레이어에 한 번만* 두고 워크플로는 조합만. 중복 자체보다 *나중에 정리하다 터지는 2차 이슈*가 비싸므로 처음부터 경계 설계.
4. **검토 먼저, 코드 나중** — 학습루프·#3에서처럼 계약→검토→구현. 프로젝트 레포에 성급히 쓰지 않음.
5. **검증 규율 내장** — 전문가는 전진하며 자기검증함. 에이전트는 그 직관이 없으니 V1(오라클 타당성)·V2(수정선택)를 흐름에 *처음부터* 박지 않으면 "확신에 찬 오답"을 양산.

## 1. 우선순위 티어

| Tier | 워크플로 | 상태 | 왜 이 순서 |
|---|---|---|---|
| 1 [지금] | 버그수정(bug-fix) | 결정론 케이스는 돌지만 신뢰성 구멍 | 가장 완성에 가까움 → 먼저 완결 |
| 2 [다음] | 코드리뷰(code-review) | 피상적(구조화 산출물 없음) | 신규기능의 전제이기도 |
| 3 [보류] | 신규기능(new-feature) | 설계는 있으나 깊은 분석 의존 | Tier 2가 서야 제대로 |
| 별도 | 학습루프(암묵지) | 방향확정·미구현 | 사용자 별도 repo 주도(`10` 참조) |

## 2. Tier 1 — 버그수정 완결

### 2.1 end-to-end 현황·구멍

| 단계 | 현재 | 구멍 = 작업 항목 |
|---|---|---|
| 인테이크·의미추론(사람용어→코드의미) | 동작(composer: intent→ckv→bm25→graph) | OK |
| 재현 — 결정론 | 동작(reproduce-first RED) | OK |
| 재현 — 비결정/타이밍 | **없음** | **WI-4** |
| 의심코드 찾기 | 부분(root-cause-lifecycle, investigative-probe) | **WI-3** |
| 근본원인 추론 | 동작(lifecycle, probe) | OK |
| 오라클 타당성(재현이 맞나) | **없음** | **WI-V1** |
| 수정 선택(최선 지점인가) | first-plausible only | **WI-V2** |
| 구현·평가·PR | 동작(틀릴 수 있는 오라클 위에 섬) | WI-V1에 의존 |

### 2.2 "제대로 동작" 정의(완료 기준)

- **결정론 버그**: 인테이크→의미→재현(RED)→근본원인(의심 라벨링)→**최선 수정(지점 검증)**→**타당성 검증된 오라클로 RED→GREEN**→회귀→PR. *V1/V2가 false-done·오수정을 막아 신뢰성 확보.*
- **비결정/타이밍 버그**: 타이밍 주입으로 재현 시도 → 성공 시 방어가드 수정 / 재현 불가 시 모니터링 로그 삽입+재발 대기(모드 9).

### 2.3 Tier 1 내부 순서(권장)

1. **WI-V1 오라클 타당성** — GREEN이 "정말 고쳐짐"을 보장(없으면 하류 전부 모래 위). *네 보고 문제①.*
2. **WI-V2 수정선택** — 올바른 지점·최선 수정(후보 생성+judge-panel). *네 보고 문제②.*
3. **WI-3 의심 라벨링** — 근본원인 찾기 품질(진단·V2에 공급).
4. **WI-4 비결정/타이밍** — 하드 클래스 확장(모드 8-9).

→ 결정론 버그수정을 V1·V2·#3로 *믿을 수 있게* 완결한 뒤 #4로 비결정까지. "한 번에 다"는 "하나도 제대로"를 깬다.

## 3. Tier 2 — 코드리뷰 완결 (모드 C)

현재 `code_review`는 피상적. 시니어 산출물이 체계적 기능으로 필요:

- entry point → 코드 플로우 정리 → **시퀀스 다이어그램**
- 목적별 모듈 → **모듈 다이어그램**
- 플로우상 **data/state 변경 추적**
- **가드/예외 조건 분석**(무엇으로 가드·필터되나)
- 깊은 검토: **상태·데이터 조작 취약점**, **부족한 가드** 식별
- **알고리즘 복잡도(time)·자원(mem/storage)·io 성능** 분석
- 안정성 vs 속도 등 **우선순위 판단**(스케줄링/우선순위 코드 적용 여부)

→ 프리미티브 **WI-1(dataflow/CFG/PDG)·WI-2(취약점/온톨로지 룰)** 가 받치고, 그 위에 **WI-C(구조화 이해 산출물 생성)** 신규 능력. (큰 영역.)

## 6. 모듈화·재사용 맵 (중복 예방)

원칙: **그래프 로직은 CKG에만 · 검색/라벨링 합성은 CKS MCP에만 · 워크플로 절차는 coding-agent 스킬에만.** coding-agent 스킬이 그래프 로직을 재구현하지 않게(=중복 원천 차단). 스킬은 단일책임으로 쪼개 워크플로 에이전트가 조합.

| 프리미티브/능력 | 사는 레이어(한 번만) | 재사용 워크플로 |
|---|---|---|
| 그래프/dataflow/CFG/PDG (WI-1) | CKG | 버그수정(값추적)·리뷰(상태/취약점)·신규(영향) |
| 취약점/온톨로지 룰 (WI-2) | CKG/CKS | 리뷰(취약점·가드)·버그수정(보안 스멜) |
| security-pattern 노출 (WI-SP) | CKS | 리뷰·버그수정 |
| 의심 라벨링 (WI-3) | CKS 합성(+coding-agent 스킬) | 버그수정(증상→의심)·리뷰(entry/추적) |
| 검색·의미추론(composer) | CKS | 전 워크플로 인테이크 |
| 다단 확장 (WI-6) | CKS | 버그수정·리뷰 |
| 재현/근본원인/probe/타이밍주입 | coding-agent skills | 버그수정 |
| 검증 규율 V1/V2 | coding-agent skills | 버그수정 →(규율) 리뷰·신규 |
| 구조화 이해 산출물 (WI-C) | coding-agent skills + WI-1/2 | 리뷰·신규 |

핵심 재사용: **WI-1(dataflow)·WI-3(의심 라벨링)·WI-2(취약점)** 는 버그수정·리뷰·신규 모두가 부르는 *공유 프리미티브* → 워크플로별로 중복 구현 금지.

## 8. 작업 방식·규율

- 각 WI는 **계약(스키마·I/O)→검토→구현** 순. 프로젝트 레포는 검토 후에만 수정. 시험 구현은 브랜치.
- 학습루프(WI-5)는 사용자가 별도 repo로 준비 — 본 시스템과 분리, cks read-only 유지(전용 MCP가 ingest).
- 문서 상태: `07`(개선안+언어별 CPG, §6 검토갱신), `08`/`09`(개정표시=`10` 우선), `10`(학습 방향), `11`(WI-3 계약), `09-sample`/`learning-backfill`(재사용 자산). 본 `12`가 최상위 계획.
