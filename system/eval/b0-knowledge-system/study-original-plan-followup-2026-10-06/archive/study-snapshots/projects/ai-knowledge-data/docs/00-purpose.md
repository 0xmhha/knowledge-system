# 00 — PURPOSE / 프로젝트 북극성 (왜 만드는가)

> **인간은 "What"에 집중하고, 시스템은 "How"를 찾는다.**
> 이 문서가 모든 설계·구현의 *최종 목적*이다. 다른 모든 문서(이론·통합·01~07)는
> 이 목적을 실현하는 *수단*이다. 작업 중 방향이 흐려지면 이 문서로 돌아온다.
> 상태: 북극성(불변 목적). 2026-06-11.

---

## 1. 비유: 서울 → 부산

- **인간 입력(What):** "서울에서 부산을 가고 싶은데 가장 적합한 경로를 찾자." — *적은 정보, 암묵지 가득.*
- **시스템(How):** 갈 방법은 많다 — 비행기(빠름·비쌈) / 고속열차(균형) / 버스(쌈·느림), 게다가 *어느 도로·어느 경유지*냐의 선택지까지.
- **결정의 본질:** "시간 우선이냐 / 균형이냐 / 비용 우선이냐"의 **기준 무게**에 따라 옵션 중 하나를 *고른다.*
- **핵심:** 그 기준 무게는 **암묵지**다. 인간은 말 안 했지만 머릿속엔 있다. → *일반화된 문서로 외부화*해 시스템에 *결정정보*로 줘야, 시스템이 정당하게 고른다.

## 2. 코딩으로 매핑

- **What** = 티켓(요청). **How** = 설계·구현의 결정.
- **트레이드오프 기준** = 속도 / 안정성 / 자원 / 지연허용 ….
- **결정적 사실 — 기준은 모듈마다 다르다:**
  - 합의(consensus) 경로 → *1초 내 합의* 조건, **속도**가 지배.
  - 블록 적용 → 체인에 안정적으로 들어가야 함, **안정성**이 지배.
  - 여유 있는 경로 → 천천히 처리돼도 됨, **지연 허용**.
- **복잡한 코드일수록 내부 모듈별 중요도가 서로 다르며, 이것이 설계에 반영돼야 한다.** 모든 코드에 같은 기준을 똑같이 적용하면 안 된다.
- → LLM에게 *"이 모듈은 무엇을 우선하는가"*를 줘야, 여러 선택지에서 **정당화된 최종 결정**을 내리고 설계할 수 있다.

## 3. 시스템이 해야 하는 것 (4단계 루프)

1. **적은 "What" 입력**을 받는다.
2. **외부화된 암묵지**(모듈별 우선순위 + 불변식 + 규칙 + 도메인)로 **How 옵션을 평가**한다.
3. **규격화된 기준으로 결정**한다 → *같은 요청은 항상 같은 결과*(출력 안정).
4. 인간이 결과를 **리뷰** → *빠진 암묵지를 채우고 틀린 것을 정정* → 기준이 갱신돼 **더 효율적인 선택지로 진화**.

## 4. 목표 수준 (over-engineering 경계)

- **완벽이 아니라 "만족할 만한 수준"의 첫 시스템.** 어느 정도 만족스러운 설계·구현을 처리할 수 있는 *시작점*.
- 그 첫 시스템이 위 4단계 루프를 돌면서 *스스로 정교해진다.* → 처음부터 모든 걸 짓지 말 것.

## 5. 설계 문서와의 연결 (목적 → 수단)

| 목적의 요소 | 실현하는 수단(문서) |
|---|---|
| 외부화된 암묵지 | SSoT(#3) + **모듈 criticality 프로파일**(불변식보다 한 겹 넓은 "우선순위 가중치") ← *점진적: 기본값 + 핵심 모듈만 명시 override, 나머지는 루프로 성장(D-013). 전 모듈 프로파일링 금지.* |
| How 옵션 탐색·결정 | best-of-N + 캐노니컬 선택(#7), constraint-assembler(#2) |
| 규격화 결정 → 같은 결과 | 출력 안정(#7) — 결정이 *명시 기준*으로 내려지므로 반복가능 |
| 리뷰 → 암묵지 보완 → 진화 | externalizer SECI 루프(#4) |
| 흔들림 없는 결정 | 사실·잣대 고정(#1) + design-freeze(#2) |
| What/How 분리 | 인간=의도, 시스템=방법 |

## 6. 한 줄 (북극성)

> **인간은 What만 말하면, 시스템이 외부화된 암묵지(특히 모듈별로 다른 우선순위)로 How를 *정당하게 결정*하고, 같은 요청엔 같은 결과를 주며, 인간의 리뷰로 암묵지를 보완해 점점 더 나은 선택을 하는 시스템.** — 그 *첫 만족스러운 버전*을 만든다.

> ⚠ 기계장치(#1~#7)는 *목적이 아니라 수단*이다. 목적은 항상 "How의 정당하고 반복가능한 결정 + 리뷰로 진화".
