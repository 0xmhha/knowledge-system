## N-11: 새 독립 평가 준비

이전 FINAL은 이미 관측했고 새 holdout으로 쓸 수 없다. 검색 튜닝 전에 새 DEV 및 독립 FINAL의 질문, 원문 gold, 독립 평가 단위, 분할, 모델/팩/ontology 조건과 임계치를 검토하고 고정한다.

기존 승인 조건을 유지한다: BGE-M3 digest `7907646426070047a77226ac3e684fbbe8410524f7b4a74d02837e43f2146bab`, 1024차원, retrieval K=10/5회, warmup2회와 warm20회, fresh CKS process3회. pack off/on × baseline/concept_text/relations/combined의8 arm을 같은 입력·데이터셋·모델에서 회전한다. 원문/신원/비밀 혼입0, strict 무인용의 오인용 증가0, Recall/MRR 변화−0.02, 중요군−0.05, p95비1.25, bootstrap10000/95%CI를 임의 완화하지 않는다. 모델의 실제 서버 버전/호스트는 새 실행에서 기록한다. 사용자의 모델을 강제로 unload하지 않는다.

CODE/WHY/POLICY/TRACE/ABS 각 중요군의 독립 FINAL 단위가10개 미만이면 descriptive/inconclusive이고 기본 활성화/출시 근거로 쓰지 않는다. 반복 실행·한영 번역·동일 사실의 바꿔쓰기·같은 fixture 상태를 별도 표본으로 세지 않는다. 질문 ID가 다르다는 사실만으로 독립성을 인정하지 않는다. 새 입력의 출처·질문/gold와 묶음 단위는 아직 준비·검토 중이며 N-11은 완료가 아니다. 결과를 보고 입력·임계치를 바꾸면 별도 DEV 버전으로 남기고 독립 FINAL을 회전한다.

## N-12/14: 실제 파일럿과 변경 수용

D5-06에 따라 첫 실제 대상은 knowledge-system 자신의 정책·ADR이다. 공통20개는 시스템 메타모델이고 산업의 사실20개가 아니다. [D1 설계 결정](./D1-DECISION-REVIEW.md), [20개 용도](./ONTOLOGY-20-USAGE.md), [파일럿 명세](./spec-pilot.yaml)의3개 요구사항/4개 기준은 설계 대표 사례로 승인됐다. 이 승인은 개별 주장·앵커·관계 또는 실제 변경의 `verified/accepted` 판정을 대신하지 않는다.

실제 내용 검토에는 source snapshot/원문 SHA, 적용 범위/권위/시점, 판정자, 승인·수정·기권과 이유가 필요하다. 실제 검토 활동 시간/비용을 기록할 때 질문 전송과 응답 사이의 대기 시간을 사람의 작업 시간으로 꾸미지 않는다. 실제 변경의 테스트 pass, 링크 존재, 원문/신원 verified, 사람의 의미 accepted를 각각 기록하고 새 후보/승격·거부·rollback으로 확인한다. 사람이 검토하지 않은 사실이나 수용 판정을 만들어 채우지 않는다.

## N-15–17: 실행 환경과 운영 사실

현재 호스트는 Darwin ARM64다. 기존 Linux 컨테이너 시험은 native Linux AMD64 호스트 실행을 대신하지 않는다. native Linux AMD64의 기존 실행 대상(호스트 또는 native CI)과 실제 대상 프로젝트/모델/외부 소비자 정보가 필요하다. 새 CI나 공개 배포가 필요하면 먼저 구체적인 변경과 전송 대상을 작성해 검토할 수 있게 한다.

운영 판정에는 실제 권한자/검토자, scope/schema, 공개키 fingerprint와 독립 신뢰 경로, 키 교체·폐기/보관 담당, native/전이 라이선스 고지 적합성 판단이 필요하다. 개인키 본문은 문서·저장소·질문에 넣지 않는다. 기존 시험 키/서명은 운영 신뢰의 증거로 바꾸지 않는다.

복구 훈련에는 실제 backup/failover 담당, 허용 복구 시간(RTO), 허용 데이터 손실 시간(RPO), 백업·키 복구 경로와 네트워크/전원 정책의 실제 호스트 상태가 필요하다. 기존 preview 복구 시험은 운영 후보의 실훈련 완료가 아니다.
