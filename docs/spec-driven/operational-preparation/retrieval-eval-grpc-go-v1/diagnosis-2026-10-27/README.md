# grpc-go 검색 평가: 고칠 곳의 코드가 팩에 들어가는가 (2026-10-27)

[앞선 진단](../diagnosis-2026-10-26/README.md)은 순위(hit@1, MRR)를 봤다. 이번에는 사용자가 정한 기준으로 본다. 사용자 메시지 원문: "중요한것은 문제를 해결할수있는 실마리 코드를 찾았는가여부야. 만약 찾지 못했다면, 찾지못한 이유를 디버깅할수있도록 준비하고, 정리후에 디버깅을 진행해."

"찾았다"는 CKS가 LLM에 건네는 최종 팩(Stage 4에서 고른 본문)에 정답 범위와 겹치는 인용이 하나라도 있다는 뜻이다(커밋과 상관없이 줄이 겹치면 적중). 표본·정답·질문은 바꾸지 않았다. 표본 확인은 사람이 아니라 AI가 사용자 위임으로 했으므로([표본 확인](../sample-check/PACKET.md)), 모든 수치는 DEV 근거다.

## 2. 정답을 건네지 못한 이유 (`9e4a0f0b`)

`scripts/retrieval_found_diagnosis.py`로 시나리오마다 정답이 어디서 빠졌는지 나눴다. 디버그 기록에 더해 두 가지를 직접 확인한다. 색인에 정답 범위와 겹치는 청크가 있는지, 그리고 같은 질문으로 벡터만 1,000위까지 찾았을 때 정답이 몇 위인지다. 이 탐침은 CKS Stage 1의 1라운드 결과 20건을 순서까지 그대로 재현했다.

|분류|qwen3|bge-m3|
|---|---|---|
|팩에 있음|39|46|
|Stage 4에서 잘림|24|24|
|Stage 2 상한에서 잘림|2|3|
|어떤 후보 목록에도 없음|35|27|
|… 색인에 정답이 없음|0|0|
|… 벡터 순위 21~1,000위|30|22|

정답 코드는 모든 시나리오에서 색인에 있었다. Stage 4에서 잘린 48건은 모두 팩이 12개보다 작았다(8~11개). 100개 팩 중 12개를 채운 것은 6개와 4개였다. 이 가운데 11건(qwen3)과 9건(bge-m3)은 시험 파일이 정답인 질문인데 의도가 `test_add`로 분류되지 않았다.

후보 목록에 오르지 못한 정답 가운데, Stage 2 상위 10개 시드에서 그래프로 한 걸음이면 닿는 것이 7건과 5건, 두 걸음이면 닿는 것이 12건과 12건이었다([tools/graph_reach.py](./tools/graph_reach.py)). 가장 흔한 길은 "시드를 호출하는 함수"였다. 이때 Stage 1 상위 8개는 시험 파일(30%, 53%), 문서와 convention 청크(21%, 4%), 생성 코드(5%, 9%)가 많이 차지했다. 다만 시험과 문서를 빼고 검색해도 20위 안에 드는 정답은 7/27과 1/19뿐이었다([tools/nontest_probe.py](./tools/nontest_probe.py)). 나머지는 한국어 질문과 정답 코드가 벡터 공간에서 멀어서 생긴다.

## 3. 표본 확인

사용자가 표본 20건 확인을 AI에게 맡겼다. 판단 근거와 결과는 [표본 확인](../sample-check/PACKET.md)의 "AI 검토"에 있다. 요약하면 평가를 무효로 할 결함은 찾지 못했다. 다만 A1과 A2에 부수 정답이 있고, B6~B9에 식별자를 한국어로 옮긴 약한 누설이 있다. 사람의 확인은 아직 없다.

## 4. 찾은 결함과 수정

결과를 보기 전에 수정과 판정 기준을 [`FOUND-FIX-PLAN.md`](./FOUND-FIX-PLAN.md)에 고정했다. 새로 찾은 결함은 그 수정의 결과를 보기 전에 같은 문서에 덧붙였다. 변형마다 커밋 `518e715a`에 그 수정만 얹은 `cks`를 빌드했다(`builds/<변형>/`).

### 4.1 시험 질문인데 시험 파일을 강등함 (`7f57734b`)

Stage 2는 의도가 `test_add`가 아니면 시험 파일 점수를 0.25배로 깎는다. 그런데 의도 분류기는 시험 질문 22건 가운데 3~5건만 `test_add`에 가장 가깝다고 봤다. 그래서 벡터 순위 1~5위였던 시험 정답이 Stage 2에서 8~26위로 밀려 잘렸다.

이제 질문 자체에 시험 낱말(시험, 테스트, test(s), flaky, e2e, fuzz, 퍼저, benchmark, 벤치마크)이 있으면 강등하지 않는다. 이 신호는 임베딩 모델이 아니라 질문을 읽는다. 측정 전에 확인한 포함률은 grpc-go 시험 질문 21/22, 다른 질문 2/78이었다.

### 4.2 쓸 후보가 없는 칸을 잡아 둠 (`10b64631`)

Stage 4는 이웃 4칸, 지식 2칸, 정확 심볼 2칸을 늘 잡아 두었다. 시드가 8칸을 채우면 지식·정확 심볼 몫 때문에 이웃도 들어오지 못했다. 이제 그 종류의 후보가 목록 뒤에 남아 있을 때만 칸을 잡아 둔다.

이 변경은 2026-08-03 결정(지식 칸은 무조건 잡아 둠, 당시 자체 평가 시나리오 하나에서 MRR 0.0038 차이)을 뒤집는다. 자체 평가는 이번에 다시 재지 않았다(7장). 팩이 12개까지 차므로 토큰이 늘어난다.

### 4.3 호출자가 이웃으로 돌아오지 않음 (`708d636a`)

Stage 3은 호출자를 팩에 넣은 적이 없었다. 원인은 두 가지다.

- 의도가 미분류이면 관계 필터를 비워 보내는데, `ckgclient`는 빈 필터를 정방향 걷기로 읽는다. 그래서 호출자를 묻지도 않았다.
- `called_by`를 걷는 의도에서도 `ckgclient`는 그래프 방향을 지켜 호출자를 `Source`에, 시드를 `Target`에 둔다. 반면 Stage 3 이후는 `Edge.Target`을 이웃으로 읽는다. 그래서 호출자 자리에 시드가 다시 들어갔다. pr-9100에서는 시드 `newInterceptor`가 자기 자신의 호출자로 두 번 돌아왔다.

이제 미분류 의도에서 `called_by`도 걷고, Stage 3이 간선마다 시드 쪽을 `Source`로 맞춘다.

### 4.5 평가 판정과 질의 세트

- **인용 커밋 판정 (`8fe67676`):** `reindex`한 색인은 바뀌지 않은 파일에 처음 임베딩한 커밋을 남긴다. 그래서 `cks eval`이 같은 내용의 인용을 커밋 충돌로 버렸다. 1차 결과 팩에서 커밋이 다른 인용은 661개와 651개였고, 그 커밋과 스냅샷 사이에 파일이 바뀐 것은 0개였다. `--commit-repo`를 주면 파일이 바뀌지 않은 인용을 점수에 넣는다. 사용자 결정 원문: "B. cks eval 판정 고치기 (Recommended)". 명세와 [계약](../../../EVAL-CONTRACT.md)을 함께 고쳤다.
- **go-stablenet 한국어 질문:** PR 본문 질의는 12건 중 8건이 정답 파일 이름을 담고 있다. 그래서 grpc-go와 같은 규칙(식별자·파일 이름 없음)으로 질문 12개를 새로 쓰고, 누설 검사(`retrieval_pr_scenarios.leaked_terms`, 정답 파일 이름과 diff 함수 이름, 0건)를 거쳐 실행 전에 고정했다(`go-stablenet/prompts-ko.json`, sha256 `4ff528ed4d32d20dabb98694e55cab52227e01bf3b70602d918fbf549706bb4f`). AI가 썼고 사람이 확인하지 않았다. 사용자 결정 원문: "A. 한국어 질문 새로 만들기 (Recommended)".

## 5. 남은 원인 (최종 빌드)

|분류|qwen3|bge-m3|
|---|---|---|
|팩에 있음|51|58|
|Stage 4에서 잘림|15|14|
|Stage 2 상한에서 잘림|1|3|
|어떤 후보 목록에도 없음|33|25|

- **이웃 순위:** 그래프가 정답 호출자를 찾아도 이웃 칸 4개 안에 들지 못한다. 이웃 점수는 시드 점수와 거리만 쓰고 질문과의 관련은 보지 않는다. 그래서 한 줄짜리 필드 정의가 같은 점수로 앞에 선다. 다음에 고칠 곳이다.
- **의미 거리:** 후보에 오르지 못한 정답 대부분은 벡터 순위 21위 밖이다. 시험과 문서를 빼도 크게 줄지 않는다. 질문의 한국어 표현과 코드 낱말을 잇는 방법(의도 판정 개선, 어휘 다리, 질의 확장)이 필요하다.
- **토큰:** 팩을 12개까지 채우면서 토큰이 약 1.5배가 됐다. 정답 하나를 더 건네는 데 드는 비용으로 따로 판단해야 한다.

## 6. 의도 판정

이번 수정은 의도 판정을 바꾸지 않았다. 최종 빌드의 의도 정확도는 qwen3 0.00, bge-m3 0.14로 그대로다. D1의 시험 낱말 신호는 의도 판정이 시험 질문을 놓치는 경우의 한 갈래만 막는다. 기준값을 모델의 유사도 크기에서 떼어 내는 일은 여전히 남아 있다.

## 7. 확인하지 않은 것

- **사람의 표본 확인:** 표본 20건은 AI가 판단했다. 사람이 확인하기 전까지 모든 수치는 DEV 근거다.
- **자체 평가 시나리오:** knowledge-system 자체 평가(`system/eval/scenarios`)는 지금 HEAD에 맞는 색인이 없어 돌리지 않았다. 4.2절이 뒤집은 2026-08-03 결정의 근거(`composer-pipeline-flow`의 MRR 0.0038)를 다시 재지 않았다.
- **요인 상호작용:** 변형은 미리 정한 조합만 쟀다. D1과 D3b만 함께 넣은 조합은 재지 않았다.
- **표본 크기:** go-stablenet 한국어 질문은 12건이라 작은 변화는 판단할 수 없다.
- **검증 방식:** 최종 빌드는 변형 빌드와 팩이 같은지 따로 대조하지 않았다. 최종 수치는 커밋한 트리(`0c509daa`)를 깨끗한 작업 트리에서 빌드해 잰 값이다.
