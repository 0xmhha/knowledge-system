WI-4 도달성·계약·독립 가족·반복 실행 공백 — 비공개 준비 자료
가설 5개/스케줄 21개/독립 가족 0개. 로컬 관측 50+20건은 운영 arm별 100회가 아니다.
과거 대역 60회/arm 및 모드9 2초 계획 창 2개는 현재 5가족 수용/600초 증거가 아니다.

SCHED-001 uninstall_status_handshake_cycle
Syncing은 buffer 없는 statuses를 SubscribeSyncStatus에 넘기고 RPC 오류/연결 종료에서 goroutine을 반환하며 Unsubscribe를 defer한다.
도달성: 실제 notifier/RPC 종료와 eventLoop 송신이 겹치는 실행을 같은 source/snapshot에서 확보할 수 있는가? 추출 대역의 송신 대기와 실제 운영 도달성을 분리한다.
계약: 종료 시각·해제 확인·추가 알림의 허용 범위와 반환 상한을 독립 오라클로 확정해야 한다.

SCHED-002 removed_list_cursor_loses_successor
실제 matcher 등록은 time.Now().Add(respTimeout) deadline을 만들며 응답 완료 시 목록 원소를 제거한다.
도달성: 합성 먼 미래 deadline을 실제 등록 경로에서 어떻게 만들 수 있는가? monotonic 시각이 유지될 때 wall-clock rollback만을 유발 증거로 삼지 않는다. 응답/timeout 제거 분기도 같은 메커니즘으로 검토한다.
계약: 한 이벤트가 처리해야 하는 matcher 범위와 실제 timer firing/재설정 계약을 독립 검토해야 한다.

SCHED-003 cancellation_and_ready_send_selection
newWorkLoop는 chainConfig.Anzeon이 nil이면 Origin, 아니면 WBFT 루프를 호출한다.
도달성: 선정 가설은 Origin 루프다. 평가 대상의 실제 chain config가 이 분기를 선택하는지와 종료·송신 동시 준비를 입증해야 한다.
계약: 종료의 선형화 지점·이미 수락한 작업 허용·select의 복수 합법 결과를 확정하기 전 단일 결과를 실패로 채점하지 않는다.

SCHED-004 cache_mark_precedes_async_delivery
Broadcast는 validator 여부를 검사하고 Gossip을 호출한 뒤 자기 메시지를 비동기로 게시한다.
도달성: 실제 대상 peer/연결/메시지 code에서 캐시와 송신 실패·반복 호출 경로를 확보할 수 있는가? 가짜 peer 성공/오류는 실제 전달 영수증이 아니다.
계약: best-effort·시도 중복 억제·전달 성공 중 캐시가 나타내는 의미와 재시도 요구를 확정해야 한다.

SCHED-005 pool_lock_held_during_synchronous_fanout
SubscribeTransactions는 reorgs=true에서 insertFeed, 아니면 discoverFeed에 구독한다.
도달성: 실제 reorgs 구독자가 수신 전 Stats/같은 lock을 기다리는 경로와 buffer 포화 조건을 입증해야 한다. 통제 subscriber 순환 대기를 운영 도달성으로 승격하지 않는다.
계약: 구독자 버퍼·수신 순서·허용 backpressure·해제 시 자원 정리와 정상 대조군을 독립 오라클로 확정해야 한다.

실행·판정 연결 질문:
T01 before/after source는 같은 driver/environment를 요구하며 repetitions는 1..1000, timeout 범위도 별도 검증한다.
미충족: 일반 API 허용 범위는 WI-4 arm별 100회·승인된 binary/환경·10분 관찰 범위를 자동 강제하지 않는다.
T02 schedule은 seed/trial의 지정 hash에서 파생하며 before/after가 같은 schedule을 쓴다.
미충족: 같은 hash schedule이 독립 가족·공정한 arm 순서·관측되지 않은 교란 요인의 독립성을 입증하지 않는다.
T03 planned/attempted/completed·symptom/control/인프라 오류·missing을 분리하고 completed에서 관측 실패율을 계산한다.
미충족: 승인된 유효 반복 분모·오류/취소/재시도·가족별 집계 및 선택 편향 처리 정책이 필요하다.
T04 generic verdict는 최소 추론 표본과 MinCompleted를 검사하고 after의 UpperFailureRate95를 MaxFailureRate와 비교한다.
미충족: 기존 최소 추론 표본 30과 수정 후 절대 상한 판정은 WI-4의 100회·baseline 대비 비율<=0.50·독립 가족 수용 판정과 다르다. 범위별 판정 연결이 미동결이다.
T05 UpperBinomial95는 단측 95% Clopper-Pearson 관측 창 상한을 계산한다.
미충족: 프로토콜의 paired family-cluster bootstrap 제안과 같은 구간이 아니다. 상대 비율·가족 불확실성/undefined 처리와 매칭을 별도로 확정해야 한다.
T06 trial context와 분리한 cleanup context를 만들고 cleanup 오류를 ERROR로 보존한다.
미충족: 실제 대상 노드의 소유권·환경 pin·취소/정리 영수증과 기존/외부 노드 비정지 경계를 확보해야 한다.
T07 구조화 log 관찰은 AWAITING_OBSERVATION으로 시작하고 종료 시각까지 source/환경을 관찰한다.
미충족: 짧은 대역 창의 무재발은 수정 성공이 아니다. 대상 600초 창·초기 log anchor·오류와 불충분 관측의 연결 규칙이 미동결이다.
T08 지정 symptom log를 source identity로 재확인한 뒤 RECURRED와 resume_requested를 반환한다.
미충족: 실제 target의 event 의미·재발/변조/취소/미재발 경로 및 분석 역할 재진입 영수증이 필요하다.
T09 MCP experiment 도구는 bounded input을 decode하고 application experiment를 호출한다.
미충족: 도구 구현과 과거 host 연결만으로 현재 5가설의 실제 baseline/fix·설치된 역할 흐름을 검증했다고 볼 수 없다.
T10 구조화 log 관찰 도구는 노드 제어 없이 관찰하고 원인/수정 수용을 판정하지 않는다고 명시한다.
미충족: 주입 comparison과 read-only mode9 관찰의 source/권한/영수증을 혼합하지 않고 단계별로 연결해야 한다.
T11 같은 normal/race suite·build/vet 통제 결과에서도 timing_neutrality=not_proven과 acceptance=not_recorded를 유지한다.
미충족: 로깅의 스케줄 영향·오버헤드 효과와 불확실성 평가가 없다. 통제 테스트 통과를 timing neutrality로 승격하지 않는다.
