WI-4 원문 가설·스케줄 후보 — 2026-10-16

목적과 현황
동일 증상의 스케줄 변형을 서로 다른 독립 가족으로 세는 오류를 막고,
실제 원문에 근거한 후보·관측·정리 조건을 독립 검토 전에 준비한다.
가설 후보 5개(기존 1개+신규 4개), 스케줄 21개, 원문 근거 17곳/7파일.
후보 간 중복 검토 10쌍은 모두 미승인이다. 승인된 독립 가족은 0개다.

후보별 범위
SCHED-001 구독 해제와 알림 송신
  정상·송신 대기·추가 알림·확인 지연·동시 해제의 5개 스케줄.
  기존 추출 메서드 로컬 증거만 존재한다. 실제 API 도달성과 발생 빈도는 미확인.
SCHED-002 목록 삭제 후 다음 원소 순회
  정상·먼 deadline 2개·먼/가까운 deadline 혼합·응답/timeout 분기의 4개.
  응답·timeout·clockwarp는 같은 제거 커서 문제의 분기로 묶는다.
  먼 deadline은 합성 입력이다. 호스트 시계를 변경하지 않는다.
  Go 1.26.9에서 Now.Add와 Sub는 monotonic 값을 사용할 수 있으므로,
  wall-clock rollback만으로 이 경로를 재현했다는 주장을 하지 않는다.
SCHED-003 종료 신호와 새 작업 송신
  정상·exit만 준비·송신/exit 동시 준비·backlog의 4개.
  closure의 반환과 외부 worker 반환을 구별한다. select의 선택 순서는 고정하지 않는다.
  종료 후 이미 진행 중인 작업의 허용 범위가 미정이므로 계약 질문으로 유지한다.
SCHED-004 송신 전 캐시 기록과 실패/지연
  성공·실패 후 동일 요청·송신 완료 전 중복·새 cache/hash 대조군의 4개.
  실제 네트워크 대신 가짜 peer로 설계한다. 중복 억제는 의도된 best-effort일 수 있다.
  재시도·전달 보장 계약을 정하기 전 결함이나 손실률로 채점하지 않는다.
SCHED-005 잠금 유지 중 동기 이벤트 전달
  수신 후 조회·수신 전 조회/잠금 대기·빈 버퍼·구독 해제의 4개.
  Reset의 pool 잠금·동기 Send·Stats 잠금으로 대역의 조건을 구성한다.
  Feed는 충분한 버퍼를 권고한다. 실제 subscriber의 조회 순서는 미검증이다.
  느린 구독자의 backpressure 자체를 결함으로 판정하지 않는다.

표본·실행 규칙
arm별 100회와 baseline 증상 10건은 기존 프로토콜의 제안값이다.
이 자료 작성으로 실행을 승인하거나 충족 처리하지 않는다.
baseline 또는 후보 수정 버전·gold·담당자·DEV/FINAL·통계 독립성은 확정하지 않았다.
관측은 스케줄/arm/snapshot별로 묶어야 하며, 같은 가설의 반복은 독립 가족을 늘리지 않는다.
baseline 증상이 없거나 부족하면 inconclusive다. 0/0을 개선·성공으로 계산하지 않는다.
각 스케줄은 단계별 2초 상한·관측 후 구조·타이머/구독/잠금/소유 goroutine 정리를 명시한다.
노드·외부 모델·호스트 시계 변경·실제 프로젝트 상태 쓰기는 모두 0이다.

자료 경계와 검증

private-schedules.json과 source_fact_draft는 비공개 AI 검토 자료이며 실행 프롬프트에 주입하지 않는다.
Git commit→tree→blob→행/byte 위치를 오프라인 검증한다.
