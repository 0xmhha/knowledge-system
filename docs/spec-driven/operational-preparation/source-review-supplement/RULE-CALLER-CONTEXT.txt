원문에 결합한 AI 계약 초안 — 모두 미승인
1. 명령 이름과 후속 인자
   literal 명령 이름을 넘기는 호출에서도 flag/env/이미지/경로 등 후속 인자가 있다.
   현재 parameter-command-name 규칙은 명령 이름의 후보 흐름만 본다.
2. 린터 경로
   doLint는 cachedir flag를 downloadLinter에 넘기고 반환 linter를 명령 이름으로 전달한다.
   downloadLinter에는 checksum 파일의 version, OS/arch, archive 다운로드·해제,
   filepath.Join(cachedir,base,"golangci-lint") 반환 코드가 있다.
   checksum/해제 구현·실제 파일 신뢰·cachedir 권한·공격자 제어는 별도 미확인이다.
3. wrapper와 실행 gate
   두 wrapper는 exec.Command(cmd,args...)를 MustRun에 전달한다.
   MustRun은 명령을 표시하고 !DryRunFlag 분기에서 cmd.Run을 호출하며 오류는 log.Fatal로 넘긴다.
   WithOutput에는 ticker/goroutine과 defer 코드가 있다. 실제 자원 수명/오류 종료는 시험하지 않았다.
4. CI 진입점
   CI 파일에는 none build constraint와 명시적 go run 사용 설명이 있다.
   main은 os.Args[1]에 따라 lint/docker/debsrc/nsis 등의 함수로 분기한다.
   이 소스 배치는 운영 서비스의 요청 처리 경로나 실제 CI 실행 조건을 증명하지 않는다.
5. 후보 수와 독립성
   두 후보는 같은 build util의 유사 wrapper다. 호출자 14개를 추가 독립 결함으로 세지 않는다.
   gold·reviewer·approval·DEV/FINAL·실제 명령/호출자 계약 수용은 모두 미확정이다.
