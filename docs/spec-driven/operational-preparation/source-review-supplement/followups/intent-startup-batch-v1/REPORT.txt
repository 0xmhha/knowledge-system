목적: 기존 anchor65개·전처리·threshold0.55·모델 식별을 유지하면서 fresh CKS의
시작 embedding HTTP66건(차원 probe1 + anchor65)을2건으로 줄인다. 같은 provider의

임의 절단하지 않는다. batch 실패 뒤 scalar 재시도는 하지 않는다.

추가로 발견한 실제 결함: 계측 래퍼가 선택 인터페이스를 가렸다.
첫 보완으로 intent BatchEmbedder를 보존했으나, 실제 원문 응답을 비교한 검사에서
계측 CKG의 ValueAnalysisClient도 사라져 partial 대신 unavailable인 것을 확인했다.
정상 process exit를 출처 전달 성공으로 처리하지 않는다. 원래/계측/보정 시도 전부 보존한다.
최종 보완은 제공된 CKG 선택 기능의 정확한 조합16개를 보존한다. 값/규칙/확장 위임은
context·입력·partial·오류를 그대로 전달한다. annotation은 method set만 보존하며,
사용자가 미룬 보안 정답/ACL/비공개/위조 평가는 실행하지 않았다.

실제 로컬 관찰: 초기4 + 계측 보완6 + 출처 보완6 =16 CKS sessions.
8개는 의도한 공급자503/잘못된 cardinality로 listen 전에 시작을 거부했다.
정상 process exit8 중 초기 계측1건은 출처 unavailable로 실패한 증거다.
나머지7건만 동일 출처 partial을 확인했다. 최종6개 중 정상3건의 입력별66벡터
(차원 probe 포함)를 text 기준으로 대응시켜 predeclared 수치 기준을 검증한다.
같은 기본/계측 startup 모두 embedding HTTP66→2이며, 논리 embed_batch1회/65행과
실제 HTTP를 구분한다. HTTP 요청 수는 inference item 수가 아니다. 모든 session은
강제 종료 없이 EOF/거부 후 reap·reader join·group0. 원본/소유2248파일 전후 동일이다.
같은 binary와 source/model/data pin을 사용한다. 전체 native의 최종 test fixture와
