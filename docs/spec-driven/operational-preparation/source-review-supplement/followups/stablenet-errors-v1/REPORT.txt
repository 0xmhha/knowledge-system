41단계 — SN-P03 출처·무결성 오류와 임베딩 실패의 분류·복구 / 완료
검증일: 2026-10-18 (KST)

목적과 계약
- 출처 누락·무결성 오류를 모델 장애로 기록하던 문제와, 한 번 모델 장애로 기록되면 Health만으로 복구되지 않던 고정 상태를 해소했다.
- query-vector 생성 실패는 ckv.ErrEmbeddingFailed로 구분하고 원래 provider 오류를 errors.Is로 보존한다. provider 자체 timeout은 임베딩 실패지만 caller context 취소/기한 만료는 공유 모델 상태를 오염시키지 않는다. 문자열이 같다는 이유로 모델 장애를 판단하지 않는다.
- 출처/무결성/store/budget/unknown 오류는 모델 관측을 새로 set/clear하지 않는다. source_missing/snapshot_mismatch를 특정 코드로 유지한다. Health는 캐시된 모델 사용 가능성이지 모든 corpus 원문의 완전성 증명이 아니다. 원문 검증은 계속 fail-closed다.
- 양성·음성 모델 관측 모두 5초 뒤 다시 확인한다. 성공한 raw 검색은 음성 캐시를 즉시 지우고, Health만의 재확인으로도 서비스 가능성이 회복된다. 취소된 probe는 캐시에 기록하지 않고 빈 probe 응답은 실패다.
- semantic_search 오류와 v2 composition 오류는 bounded code/message로 전달한다. embedding_failed, request_canceled, request_timeout, source_missing, snapshot_mismatch를 구별하며 알 수 없는 semantic 오류는 retrieval_failed다. v2의 모델 사용 가능성 gate 거부는 service_unavailable이다.
- 선행 archive 검증은 임베딩보다 먼저 원문 오류를 거부할 수 있다. 이 legacy context guard도 구체적 코드/제한된 메시지를 사용하도록 보완했다. provider 오류 본문의 source_missing 문자열이 typed 임베딩 실패를 가리지 못한다.

- 이전 바이너리: 기존 데이터의 실제 source_missing 뒤 model_reachable=false가 되는 문제, 임베딩503 뒤 endpoint를 복구하고 TTL을 넘겨도 Health가 계속 false인 문제를 재현했다.
- 수정 바이너리: 기존 데이터의 실제 source_missing 뒤 모델 정상·알려진 정상 v2 검색 성공을 확인했다. 신규 소유 버전의 실제 검색에 노출된 외부 blob을 삭제/변조해 각각 source_missing/snapshot_mismatch를 확인했고, 원본 bytes/mode 복구 후 정상 검색/v2가 성공했다.
- 실제 서비스 연결 경로의 소유 중계 endpoint에서만 503·빈 embedding 응답을 주입했다. 둘 다 embedding_failed·즉시 모델 false로 분류했고 v2 gate는 service_unavailable로 거부했다. 공유 Ollama를 실제 중단하거나 재설정한 시험이 아니다.
- 중계 endpoint 복구 후 TTL+Health만으로 true가 되고 v2 성공, 별도 실패 후 raw 검색 성공으로 즉시 true, Health probe 자체 실패/복구 경로까지 검증했다. 프로세스 재시작 없이 같은 세션에서 수행했다.
- 최종 도구 요청37회·HTTP 관측898건, 최종 성공 v2 pack5개/인용54건의 좌표·원문·SHA·integrity 일치. 이는 검색/품질 recall·지연 수용이나 온톨로지 효과 판정이 아니다.

범위의 한계
- 런타임에 모델이 연결된 real adapter의 실패·복구 계약이다. 기동 시 모델 불가로 구성된 degraded dummy를 자동 real client로 재구성하는 기능은 이번 범위가 아니다.
- caller context 취소/timeout 분류는 native engine/adapter/MCP 검사 범위다. 실제 MCP 취소 notification의 전달·취소 동작은 실행/추가하지 않았다.
- Health가 true여도 누락된 원문을 안전하다고 인정하지 않는다. old 데이터의 원문 누락은 여전히 거부한다. 새 비운영 데이터만 검증했고 운영 current를 전환하지 않았다.
