# WBFT round change: timeout-triggered round bump with prepared-block justification

**Status:** verified · **Subsystem:** A1 (WBFT Consensus Core) · **Type:** B3

WBFT recovers from a stuck round (PRE-PREPARE or COMMIT quorum not
reached within RequestTimeout) by broadcasting a ROUND-CHANGE message
for round+1. The message carries the highest prepared block and its
PREPARE justification from prior rounds; a node accepts the view
change once it has collected a quorum of ROUND-CHANGE messages for
the same target round.

## Invariants
- A ROUND-CHANGE carries the highest prepared block this node has seen, so a quorum of view changes resumes from that prepared state and never from a lower round.
- ROUND-CHANGE quorum threshold matches the PREPARE/COMMIT quorum (see A1.wbft_core.quorum_calc).

## Pitfalls
- Bumping rounds without attaching the prepared-block justification when one exists: the cluster can fork by accepting two different blocks at different rounds for the same height.
