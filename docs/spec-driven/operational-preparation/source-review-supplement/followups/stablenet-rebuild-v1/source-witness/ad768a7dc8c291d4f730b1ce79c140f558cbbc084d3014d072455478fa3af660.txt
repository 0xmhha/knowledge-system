# Validating a WBFT consensus or state change before merge

**Status:** needs_verification · **Subsystem:** A1 (WBFT Consensus Core) · **Type:** B6

Procedure a reviewer or implementer follows to validate any change to
WBFT consensus or state transition so it does not silently break safety
or liveness. Run the Go unit tests for the touched package; run them
under the race detector (go test -race) whenever Core.current,
round-state, or locks are touched (see A1.concurrency.core_lock_discipline);
assert consensus health (round-0 finalization rate, quorum = ceil(N-F),
no fork/stall) via the istanbul RPC namespace (API.Status / GetValidators);
and finally run an integration/regression network test. The external
chainbench harness provides a b-wbft regression suite that boots a
multi-node WBFT network on the built gstable binary — chainbench is a
SEPARATE repo, so it appears only in prose, not as a code anchor. Mind
the regression-account funding gotcha: the default profile funds only
the validators plus one endpoint account.

## Invariants
- Any change touching c.current, round-state, or consensus locks must pass `go test -race` on the touched package before merge.
- After the change, observed quorum behaviour must match QuorumSize = ceil(N - F); a finalization that succeeds with fewer commits indicates a broken safety bound.
- Round-0 finalization rate must not regress and no fork/stall may appear in istanbul.status RoundDistribution after the change.

## Pitfalls
- Relying on unit tests alone for a consensus change: low-contention unit tests rarely interleave the goroutines that expose a race in c.current — only `go test -race` and a multi-node network surface it.
- Skipping the integration/regression network test because unit tests are green: safety/liveness bugs (forks, stalls) only manifest with multiple nodes and adversarial timing under chainbench.
- Default chainbench profile funds only validators + one endpoint account; a regression that appears to fail on consensus may actually be an unfunded-account error — fund extra accounts explicitly.
