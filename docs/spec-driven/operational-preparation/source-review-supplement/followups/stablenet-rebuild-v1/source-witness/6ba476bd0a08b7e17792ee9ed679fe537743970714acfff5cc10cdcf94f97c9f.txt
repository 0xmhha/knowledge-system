# Procedure: adding a new hardfork to go-stablenet

**Status:** verified · **Subsystem:** A7 (Hardfork & Chain Config) · **Type:** B6

Adding a hardfork requires changes in seven distinct sites:
ChainConfig field, isFork check method, Rules struct + Rules() build,
runtime branch in the relevant subsystem, optional NativeManager
switch update, optional system contract version pinning via
CollectUpgrades, and updates to SetConfigFromChainConfig when WBFT
parameters change. The block number must be >= the previous fork's
block number; switch-case ordering must place the newest fork on top
because the first matching case wins.

## Invariants
- Each new fork's block number must be >= the previous fork's block number (enforced by CheckConfigForkOrder).
- CollectUpgrades must return entries in ascending block order; the WBFT runtime breaks on the first block > target, so out-of-order entries silently lose later upgrades.
- In ActiveNativeManagers, the newest fork case must appear first because Go switch-case picks the first matching branch.

## Pitfalls
- Adding the new ChainConfig field but forgetting Rules + Rules() update — runtime branches never fire because rules.IsMyNewFork is always false.
- Skipping CollectUpgrades registration — the fork's system contracts never deploy at the activation block.
- Skipping SetConfigFromChainConfig update — WBFT parameter changes never reach the consensus engine.
- Adding the new switch case at the bottom of ActiveNativeManagers — an older fork above matches first and the new addresses are ignored.

## Code anchors
- `params/config.go` ChainConfig — fork block field and IsXxx methods live here
- `params/config.go` ChainConfig.CollectUpgrades — ascending-block-order upgrade registry
- `params/config.go` ChainConfig.CheckConfigForkOrder — enforces that each fork's block is >= the previous
- `eth/ethconfig/config.go` SetConfigFromChainConfig — binds ChainConfig hardforks into the WBFT runtime config
- `core/vm/native_manager.go` ActiveNativeManagers — newest-fork-on-top switch ordering rule
