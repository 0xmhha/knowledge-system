# Blacklist check points along the state transition path

**Status:** verified · **Subsystem:** A11 (Transaction Types, Mempool & State Transition) · **Type:** B3

When rules.IsAnzeon is active, a transaction can be rejected for
blacklist reasons at four distinct points before its state changes
persist. Three live in core/state_transition.go TransitionDb (Sender,
Recipient, FeePayer) and one lives in core/vm/evm.go Call (zero
address / native precompile transfer). Adding a new transaction type
or a new transfer path requires confirming every one of these gates
still fires; missing one creates a route by which a blacklisted
account can move value.

## Invariants
- Every blacklist check is gated by rules.IsAnzeon — pre-Anzeon nodes do not apply these guards.
- msg.To == nil indicates contract creation; the Recipient (②) check intentionally skips this case.
- FeePayer (③) check fires only when st.msg.FeePayer is non-nil, i.e. for fee delegation transactions; it must run before any balance debit from the FeePayer.
- Zero-address (④) and precompile-transfer guards run inside EVM.Call, so they catch CALL/CALLCODE/DELEGATECALL transfers that did not go through TransitionDb.

## Pitfalls
- Adding a new transaction type that introduces an alternative balance-debit path without re-running checks ①~③ — funds can move from a blacklisted account.
- Adding a new transfer opcode handler that bypasses EVM.Call (or that calls a lower-level routine) — check ④ is missed and zero-address / precompile transfers leak through.
- Reading 'contract creation exempt from check ②' as 'contract creation exempt from all blacklist checks' — Sender (①) still applies to the contract creator.
- Wiring FeePayer (③) check after the FeePayer balance debit instead of before — the debit happens even when the FeePayer is blacklisted, leaving inconsistent state on a rejected tx.

## Code anchors
- `core/state_transition.go` in StateTransition.TransitionDb:505 (loc) — check ①: Sender (msg.From) blacklist — ErrBlacklistedAccount returned
- `core/state_transition.go` in StateTransition.TransitionDb:509 (loc) — check ②: Recipient (msg.To) blacklist — contract creation exempt because msg.To == nil
- `core/state_transition.go` in StateTransition.TransitionDb:577 (loc) — check ③: FeePayer blacklist — only when st.msg.FeePayer != nil and rules.IsAnzeon
- `core/vm/evm.go` in EVM.Call:213 (loc) — check ④: inside the AnzeonEnabled() gate (evm.go:210) — zero-address transfer block (ErrZeroAddressTransfer at :213) and native-manager/precompile transfer block (ErrValueTransferToPrecompile at :217)
- `core/vm/evm.go` EVM.Call:195 — additional caller blacklist guard inside EVM.Call when rules.IsAnzeon is active
