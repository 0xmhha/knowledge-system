원래 조건200ms 절대시한·1초 worker·owner socket 유지·반환 후1.1초 관찰을 계측한400회 중2회가 같은 증상으로 실패했다. 두 파일은 모두 syscall.Kill 호출 전후 시각 사이에 생성됐고 guardian 반환 시점에 이미 존재했다. 하나는 내용late, 하나는 생성만 되고 빈 파일이었다. stat 오류나 반환 이후 새 생성은 이 실패들에서 관측하지 않았다. 운영 종료 코드의 계측을 제거하고 같은 관찰용 시험만 실행한 추가400회는 재현0이었다. 계측이 드문 실행 순서에 영향을 주므로 이 추가 비재현도 보존하며 과거 최초 사건의 내부 순서를 증명하는 것으로 해석하지 않는다. sleep이 먼저 종료되고 기다리던 셸이 뒤의 printf를 잠깐 실행한 시험 fixture의 오탐 원인을 실제 경로에서 확인했다.
같은 계측 소스에서 sleep1;printf를 sleep1&&printf 한 줄만 바꾼 대조군400회가 모두 통과했다. 시한200ms·worker1초·관찰1.1초와 모든 시도/실패를 유지했다. 기존397/400·대조394/400에서 실제 worker가 시작됐으며 나머지는 시한이 먼저 지나 시작하지 않은 경우로 분리한다. 시작된791개 worker 그룹을 읽기 전용 대조해 잔여0을 확인했다. 채택한 변경은 시험 파일1개이며 취소 fixture도 같은 대기 성공 조건을 사용한다. 운영 종료 구현은 변경하지 않았다.
별도 새 시험은 writer 준비를 확인하고 guardian 반환 후에만 release 파일을 만든다. owner socket은 계속 열어 두어 absolute deadline만 종료 원인이 된다. 이 검사는 일반/race 각각3회 통과했다. 실제 후손을 남기도록 임시 overlay에서 parent만 종료하고 quiescence를 생략한 mutant는 기대한 post-return writer 오류로 실패했다. 후손이 살아남는 진짜 오류를 통과시키는 수정이 아니다.
첫 mutant는 bytes.Buffer용 상속 출력 파이프가 Cmd.Wait를 붙잡아30초 시험 제한에 도달했다. 소유 고유 경로·그룹을 확인하고 release를 열어 회수한 기록과 실제late 파일을 보존했다. 정식 시험은 진단용 일반 파일을 사용해 파이프 대기가 post-return 판정을 가리지 않는다. 이 하네스 실패는 운영 코드 결함으로 세지 않는다. 최초 진단 overlay 지역변수 컴파일 오류도 원자료로 보존했다.
과거 최초1회에는 파일 존재/mtime/조회 오류/반환 시각 상세가 없다. 원래 실패의 원자료를 그대로 보존하며 그 특정 사건의 정확한 내부 순서를 사후 확정했다고 주장하지 않는다. 확인한 것은 같은 소스·조건에서 재현된 실패 유형의 인과와 시험 오탐 수정이며 모든 종료 경로/환경의 무결함 증명은 아니다.
기본 전체 build/test/race/fmt/vet/고정lint/docs를 새 고정 소스로 확인한다. CoreML은 사용자 제외를 유지하며 별도 프로필/모델 호출0·실제 모델/LLM/유료0·독립승인0·정식0/9·부모0/13·게시0이다. 현재 작업 원장은 WI-V1 등 남은13묶음을 별도로 유지한다.
