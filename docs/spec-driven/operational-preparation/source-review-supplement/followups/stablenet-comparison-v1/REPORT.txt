실제 검색 경로
- 공개된 진단 질문6개를 각 프로젝트에 동일하게 keyword, Go vector, 전체 vector, v2로 요청했다. raw 36회는 go-stablenet 성공18회와 working-tree go-wemix의 기대한 requires_v2 거부18회다. 두 프로젝트의 v2 12회는 모두 성공했다. legacy raw 순위를 양쪽에서 동등하게 비교했다고 주장하지 않는다. 빈 keyword 결과는 기능 부재로 채점하지 않았다. 입력/빈 결과/실패/응답 분모는 원시 wire·attempts·search-results.json에 보존한다.
- 최종/초기 진단의 인용 검사 합계1010건, 최종 v2 본문119건을 각 선택 archive의 좌표·원문·범위·SHA와 대조했다. non-citable convention metadata0건은 원문 인용으로 세지 않았다. 이는 무결성/격리 검사이며 의미 관련성100%나 독립 정답 수용이 아니다.
- raw Text는 원문 본문이 아니라 색인된 힌트다. flow_step 설명은 보관 corpus의 prose+symbol+branch 조건에서 재계산하고 코드 anchor는 별도로 검증한다. invariant 문구도 추출된 힌트이며 줄 전체의 인용문으로 취급하지 않는다. source/density 축약을 포함한 고유86개 힌트 투영을 실제 선택 vector DB와 대조했다. v2/비교 body는 실제 보관 원문 byte·범위 hash와 엄격히 일치했다. 초기 preflight의 Text=code 가정 실패와 수집기 보완도 보존했다.
- legacy raw hits에는 프로젝트 좌표가 자체 포함되지 않는다. 이번 검사는 명시적으로 선택한 서버 설정/버전과 원문을 결속했다. 여러 프로젝트 결과를 합치는 소비자는 v2/비교의 전체 좌표를 유지해야 하며 path·canonical ID·node ID만으로 출처를 추정하면 안 된다. working-tree legacy raw 요청은 requires_v2로 거부되며 v2의 source mode·전체 좌표·보관 원문 SHA를 함께 확인한다.
- 실제 두 저장소는 같은 모듈/canonical 함수 이름을 공유한다. types.Transaction.Size를 각 프로젝트에서 따로 조회해 서로 다른 원문 SHA를 확인했다(node ID 관측: 서로 다름). node/canonical 이름만으로 전역 신원을 만들지 않고, 다른 프로젝트 commit·잘못된 source/snapshot pin6건은 source_mismatch/analysis=null, go-wemix의 WBFT 전용 node는 not_found였다. 정확 pin 복구 조회도 성공했다.
