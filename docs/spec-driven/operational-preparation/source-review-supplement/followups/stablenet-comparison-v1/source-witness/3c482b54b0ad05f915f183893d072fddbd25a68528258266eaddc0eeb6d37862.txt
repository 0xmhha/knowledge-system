# Transaction type taxonomy and txpool admission fork gates

**Status:** verified · **Subsystem:** A11 (Transaction Types, Mempool & State Transition) · **Type:** B1

StableNet inherits geth's typed-transaction envelope and adds one
proprietary type. The full taxonomy (core/types/transaction.go) is:
LegacyTxType 0x00, AccessListTxType 0x01, DynamicFeeTxType 0x02,
BlobTxType 0x03, SetCodeTxType 0x04, and StableNet's
FeeDelegateDynamicFeeTxType 0x16 (decimal 22) for fee-delegated txs.

Pool admission runs through txpool.ValidateTransaction (core/txpool/
validation.go). After a per-pool capability check (opts.Accept bitmask)
and a size check, each non-legacy type is gated behind a fork
activation, in this source order: any non-legacy type requires Berlin;
DynamicFee additionally requires London; FeeDelegateDynamicFee requires
Applepie (StableNet's fee-delegation fork); Blob requires Cancun;
SetCode requires Anzeon (checked via AnzeonEnabled(), a global enable
rather than a block-number gate). A type whose fork is not yet active
is rejected with core.ErrTxTypeNotSupported before any signature or
state work.

After the common gas/fee/sender checks, fee-delegated txs get an extra
admission gate: types.RecoverFeePayer(chainID, tx) requires a declared
FeePayer (else types.ErrFeePayerNotSet), recovers the fee-payer signer
via FeePayer(NewFeeDelegateSigner(chainID), tx), and rejects with
types.ErrInvalidFeePayer when recovery fails or the recovered address
does not equal the declared FeePayer. This is
the stateless half; the stateful fee-payer balance check lives later in
ValidateTransactionWithState (ErrFeePayerInsufficientFunds).

## Invariants
- A non-legacy tx type is rejected from the pool until its activating fork is live (Berlin for any non-legacy, London for DynamicFee, Applepie for FeeDelegateDynamicFee, Cancun for Blob, Anzeon for SetCode).
- A pool only admits tx types whose bit is set in opts.Accept; otherwise ErrTxTypeNotSupported is returned before any other validation.
- A FeeDelegateDynamicFee tx is admitted only if it declares a FeePayer and the signature-recovered fee-payer address equals that declared FeePayer, else ErrInvalidFeePayer.
- Fork gating is purely stateless (block number / global enable); fee-payer balance sufficiency is checked separately in ValidateTransactionWithState.

## Pitfalls
- Adding a new tx type constant in transaction.go without adding a matching fork gate in ValidateTransaction lets the type into the pool unconditionally, regardless of fork activation.
- Anzeon is gated via AnzeonEnabled() (a global boolean), not via a block-number predicate like the other forks; copying the IsX(num) pattern for it is wrong.
- The fee-payer check in ValidateTransaction is stateless signature recovery only; forgetting the corresponding ValidateTransactionWithState balance check would let an underfunded fee-payer tx be accepted.
- FeeDelegateDynamicFeeTxType is 0x16 (decimal 22), not contiguous with the 0x00..0x04 range; off-by-one or range-based type handling will miss it.
