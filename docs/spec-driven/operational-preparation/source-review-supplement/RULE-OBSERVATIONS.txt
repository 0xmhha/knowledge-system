WI-2 실제 통제 분석기 관측 — 준비 14단계

결과와 목적
준비 13단계의 공개 Go 원문 40개를 실제 valueflow.AnalyzeRules에 전달했다.
일반/race 두 모드에서 각각 원문 40개·대조군 14개 관측을 보존했다.
go-local-review@1.0.0 / engine 2의 후보 경로·원문 위치·조건·상한과 결정성을
검증한 개발용 연결 증거다. 프로젝트 품질이나 독립 수용 결과는 아니다.

관측 결과
- parameter-command-name: 통제 입력 20개 중 후보 있는 입력 10개·빈 결과 10개.
- discarded-conversion-error: 통제 입력 20개 중 후보 있는 입력 10개·빈 결과 10개.
- 모드당 후보 20개. 두 모드의 정규화한 원문 관측 및 대조군 결과가 일치한다.
- 각 입력은 모드별 두 번 분석했다. elapsed_micros만 0으로 정규화한 전체 결과가 동일하다.
  원문 관측 기록은 합계 80개이며, 반복 분석 호출을 별도 독립 표본으로 세지 않는다.
- AI 후보 수 제안과 일치한 입력 40개·차이 0개. 이것은 accuracy/precision/recall이 아니다.
  AI가 작성한 노출된 통제 초안이므로 독립 gold·독립 가족·신규 FINAL은 모두 미확보다.

확인한 실제 경계
- source/sink occurrence의 ID·role·도달 표시·byte/행 span을 대응시켰다.
- 후보 path는 실제 분석 node를 참조하고, 조건은 그 path의 control_dependence와 일치한다.
- 후보 ID를 pack SHA·synthetic node/snapshot/source SHA·rule·occurrence에서 다시 계산했다.
- 분기·loop·실제 shadow·병렬 RHS/kill·직접 sink/간접 sink를 통제 원문으로 구분했다.
- opaque sanitizer가 있는 RULE-1-05 / RULE-2-06은 후보를 유지하지만 not_proven이다.
- 위조 owner 객체인 RULE-1-07 / RULE-2-07도 후보가 된다. syntax_only_unverified를 보존한다.
- 별명 호출 RULE-1-15 / RULE-2-16은 빈 결과이며 실제 대상의 안전을 증명하지 않는다.
- field/expression/closure/bare return 등의 빈 결과는 지원 제한과 함께 기록한다.
- 40개 모두 isolated_type_info_partial 진단이 있다. opaque_call·external_value_unknown·
  field/reference/closure 진단도 삭제하지 않는다. 함수 문자열에는 전체 import/타입 문맥이 없다.
- range 대조군의 structural_block_unlocated 조건은 location null을 유지한다.

대조군 14종 — 각 모드에서 모두 통과
candidate cap, flow-step cap, base node cap, 취소, 기본 규칙 비활성화,
명시하지 않거나 잘못된 pack, 후보 상한 범위, flow 상한 범위,
node ID 변경, snapshot SHA 변경, source byte 변경,
range 조건 위치 unknown, 미지원 언어, 잘못된 구문.
부분·취소·미지원은 완료된 빈 탐지로 승격하지 않는다.
node/snapshot/source 변경 시 후보 ID가 재사용되지 않음을 확인했다.
기존 rule 회귀도 일반/race 각 28개 named test 완료를 별도 기록했다.

격리 및 실행 범위
기존 rules_test.go 원문을 보존하고 /private/tmp의 backing 파일을 Go overlay로 덧붙였다.
유지보수 Go 파일과 이전 동결 패킷 13개는 변경하지 않았다.
native harness에는 public-bundle/public-inputs.json과 같은 원문만 전달했다.
AI 기대 초안은 관측 이후 비교 단계에서 읽으며 native 분석기 입력에 넣지 않는다.
이는 입력 포장 분리이고 OS 파일 접근 차단을 구현했다는 의미는 아니다.
원문 속 exec.Command/sanitize/clamp 등은 실행하지 않았다.
프로젝트 실제 retained graph/MCP 경로·서버·모델·노드·실제 취약성은 시험하지 않았다.
synthetic retained 좌표 400 byte/20행과 synthetic snapshot pin은 실제 graph snapshot이 아니다.
전체 프로젝트 타입 검사와 warm 지연 측정도 하지 않았다.

검증 자료
rule-observations-v1/manifest.json: 실제 분석기·기존 테스트·template·입력·도구 설정의 hash 결합.
logs/normal.jsonl, logs/race.jsonl: 원문 80개·대조군 28개 원자료와 native 완료 이벤트.
logs/regression-normal.jsonl, logs/regression-race.jsonl: 기존 rule 회귀 56개 named test 완료.
observations.json, controls.json: elapsed만 정규화한 실제 결과.
case-review.json: source/sink/조건 원문과 AI 수량 제안 비교. gold/approval false, safety unknown.
coverage-summary.json, disagreements.json: 통제 분모·진단·미판정 범위. 품질 점수 null.
validation.json 및 build/fmt/vet/lint 로그: 새 overlay를 포함한 품질 검사 4건 통과.
기록한 native 실행은 Go 1.26.9다. checker의 재실행은 설치된 호환 Go를 사용하고
toolchain/module 다운로드는 수행하지 않는다.
checker는 신뢰하는 live template로 실제 분석기를 다시 실행해 관측과 대조하고,
후보 ID·원문 위치·조건 관계도 별도로 검증한다. 패킷에 포함된 임의 코드는 실행하지 않는다.
전용 회귀 30개가 재해시한 원자료 변조·공개 정답 혼입·가짜 위치/상한/진단·안전·
독립 승인·정식 실행·프로젝트 분모·precision/recall 승격을 거부한다.
