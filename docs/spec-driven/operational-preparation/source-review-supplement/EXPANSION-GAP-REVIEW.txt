목적
기존 expansion-v1의 입력 후보/AI 원문 검토와 실제 bounded value/context expansion 구현,
과거 실행을 연결하여 독립 가족·쌍 구성·관련성/잡음 gold·실제 경로·warm 지연의 공백을 기록한다.
입력 카드 수·source 분석·실제 fixture 실행·독립 프로젝트 수용을 구분하고 완료를 과장하지 않는다.

운영 표본·의도·독립성

  stress main은 원문만 검토하며 실행하지 않는다. 운영 독립 가족 수에 포함하지 않는다.
- 운영 제안 수로도 최소20개에 1개 부족하다. 그 부족분을 추가한다고 독립20가족이 확보되는
  것은 아니다. 현재 독립 승인 가족/관련성 gold/프로젝트 paired receipt/warm 영수증은 모두 0개다.
- 의도 label은 value_propagation4/state_guard5/error_handling5/resource_lifecycle6이다.
  운영만 보면 resource_lifecycle5이며 나머지는 같다. label4종이 독립성·표본 충분성 승인은 아니다.
- 고정 프로젝트 commit 0bf2f4d1bfeb6605006d556957ef8c045d8f8ed8의 14파일·기존 AI 근거
  40곳을 lexical packet의 Git commit→tree→blob 증명에 대조했다. source 확인은 retrieval 실행이 아니다.
- 190쌍 중 같은 파일7/같은 intent41쌍이며, 기존 노출 WI-1 함수 표본과 16seed가 겹친다.
  다른 파일/다른 intent도 의미적으로 독립이라고 승인하지 않는다. fresh holdout/DEV-FINAL은 미동결이다.
- 20개 각각에 의도별 관련성 질문과 기존 unknown·gold/seed/쌍/지연/수용의 null 상태를 기록했다.
  AI anchor는 비완전 원문 사실 제안이며 exhaustive relevance labels가 아니다.

기본/확장 쌍의 실제 의미와 미완료 사항
- 프로토콜 제안 arm은 context.value_dependencies와 context.value_dependency_expansion이다.
  기본은 정확히 선택한 함수 하나의 지역 value/control 분석이며 text/top-k retrieval이 아니다.
- 확장 입력은 Function QueryInput + Limits다. intent/prompt 필드나 text query 기반의 관련성
  순위 선택은 없다. 카드의 의도는 평가용 relevance gold에 반영할 조건이다.
- 확장 엔진은 나가는 calls/invokes만 따라가며 고유 함수별 지역 분석을 합성한다. incoming
  caller를 자동 탐색하거나 call hop을 argument/return·메모리 값 전달로 계산하지 않는다.
- error_handling 카드의 호출자 영향, 값 소비자/소유권/외부 상태를 묻는 질문은 outgoing만으로
  회수 가능한 범위인지 독립 검토해야 한다. 지원 경로에 맞춰 관련/비관련/unknown·제외를 사전 결정한다.
- 두 arm의 같은 seed/retained source·snapshot·local limits를 명시하고, 확장에만 있는
  functions/hops/candidates/aggregate node-edge-fact/time cap의 대응·전체 예산을 별도로 동결한다.
  두 API에 같은 형태의 전체 limit 객체를 넣는다는 뜻으로 '동일 상한'을 쓰지 않는다.
- 현재 프로젝트20카드의 retained node/canonical resolution·snapshot pin·실제 baseline/expansion
  request·arm order/retry·paired receipt는 null이다. 현재 실행한 것처럼 가짜 node/pin을 채우지 않는다.
- 반환 wrapper와 유효 analysis가 있는 고유 함수, call hop, 지역 value/control 근거, curated
  metadata의 반환/평가 단위를 구분한다. 순환/dedup/partial/analysis null·미지원/상한/오류/기권의
  분모·coverage를 유지해야 한다. 반환 원소 수를 독립 가족 수로 세지 않는다.

완전한 관련성·잡음 정답과 매칭
- 20개 모두 independent_relevance_gold/negative_and_unknown_labels/universe/completeness가
  null이다. 미작성 gold를 빈 정답으로 대체하거나 비관련 반환으로 임의 분류하지 않는다.
- 독립 검토자가 seed 포함 여부, 관련 target과 근거·완전성 범위·단순 호출 이웃/관련 함수의
  차이, 비관련/unknown/미지원의 이유를 작성해야 한다. 의미 gold와 실제 출력은 별도로 보관한다.
- project/commit/snapshot/canonical function/blob hash·원문 위치와 중복 정책을 동결한다.
  node ID 또는 함수 이름만으로 다른 프로젝트/수정본·snapshot의 대상을 합치지 않는다.
- recall은 관련 반환/전체 관련 정답, noise는 비관련 반환/전체 반환이다. case/family macro 집계,
  case별 복수 의도/동일 가족·빈 gold·빈 반환·실패/상한/미지원의 처리와 coverage는 미동결이다.
- protocol empty_return_noise_fraction은 null이다. 빈 반환을 noise0·안전 성공으로 채우지 않는다.
  기존 실패/기권 구분을 유지하면서 독립 검토로 수용 mapping을 확정해야 한다.
- 제안 recall delta>=0.10/noise delta<=0.10은 fraction difference, 즉 10 percentage points다.
  비율 10% 개선이나 상대 감소율로 바꾸지 않는다. 현재 점수와 독립 수용 판정은 null이다.

현재 source/MCP/public client와 소비자 노출
- 현재 구현 7파일의 SHA, 계약12곳의 line/byte/span SHA와 채택 consumer2파일의 Git/채택 SHA를

  재확인하며 partial/budget/source mismatch를 보존한다. 이것을 모든 path feasibility 보장으로 세지 않는다.
- consumer schema에 두 도구가 있고 현재 CKS input metadata와 일치한다. 하지만 Analyzer의

  직접 alias가 없다. 기본/확장 사용을 연결하는 의도별 역할 정책과 실제 설치 노출·권한·호출·typed
  handoff 영수증은 미확보다. metadata parity를 실제 역할 성공이나 실제 거부 증명으로 쓰지 않는다.
- curated_flow는 operator_curated_metadata/separate_not_joined/source_association:not_verified다.
  자동 argument/return transfer, 검증된 graph/vector dataset join 또는 ontology 효과를 주장하지 않는다.
- 이번 단계에서 현재 프로젝트 MCP/host/모델·노드를 실행하거나 외부 consumer checkout을 변경하지 않았다.

과거 실제 작은 fixture 실행의 성과와 한계
- 과거 WI-6에는 컴파일/race 검증한 6함수 fixture의 실제 CKG7/CKS13요청 기록이 있다.
  원래 요청/응답 ID를 대조하고 단일 seed의 baseline 요청과 확장 function 입력이 같으며,
  snapshot과 seed local limits도 같음을 확인했다. 확장에는 max_functions8/max_hops3 등 별도
  aggregate limits가 있다. 요청 13개를 13독립 가족 또는 반복 benchmark로 세지 않는다.
- baseline은 Seed 한 함수, 확장은 Seed/Noise/Cycle/Transform/Normalize5함수다.
  fixture가 선언한 관련 target4개에 대해 기본1/4→확장4/4, 잡음1/5로 기록했다.
  cycle/dedup·source pin·curated 분리·isolated/stale/invalid input·5종 cap·원문 삭제 뒤 retained
  실행 성과를 보존했다. 이 성과는 현재 프로젝트20카드/독립 가족20개·독립 사람 수용이 아니다.
- 선언 fixture labels를 기준으로만 계산하면 recall delta=.75, baseline noise0→expanded noise.20다.
  .20을 숨기거나 제안 .10을 충족했다고 쓰지 않는다. 독립 gold·분모·품질 기준 동결이 없으므로
  이 산술을 정식 WI-6 pass/fail로 전용하지 않는다.
- 기록된 서버 내부 elapsed는 기본1431µs/확장2875µs로 단일 비율 약2.0091이다.
  warm 정의·반복 표본·p95가 없으므로 warm p95<=2.0의 통과 또는 실패 근거가 아니다.
  과거 실행 성공과 남은 품질/지연 수용을 각각 보존한다.

warm 지연 계약의 미동결 사항
- 같은 측정 경계(client end-to-end/CKS facade/server Query·Expand), monotonic clock과 timestamp
  원자료를 정한다. 현재 서버 elapsed는 transport/직렬화/소비자 비용을 포함하지 않는다.
- warm 정의·초기 제외/안정화·세션/프로세스/연결 재사용·OS/DB/cache 상태·하드웨어/runtime·자원
  상한을 동결해야 한다. 다른 평가의 warm20 반복 조건을 자동으로 수입하지 않는다.
- 가족/arm별 반복 최소치, p95 quantile/interpolation, arm 순서·동시성, 실패/timeout/상한/취소/
  retry·이상값 처리와 원래 분모, 측정 해상도·0/누락/극소 baseline 처리가 미정이다.
- p95(expansion)/p95(baseline)과 paired ratio의 p95는 다르다. ratio 정의·family 집계·불확실성과
  충분성 기준을 확정하고 실제 warm 원자료/환경/source pin 영수증을 수집한 뒤 판정한다.
- 패킷의 warm_definition/warmup_count/repetitions/order/clock/p95/ratio/raw_samples/score는 null이다.
