목적
개발용 구독 티켓·AI 수정 후보/변이·추출 메서드 관측을 실제 프로젝트의 API/종료 계약,
채택 coding-agent의 oracle/선택/역할 경로와 대조한다. 이미 구현되고 실행된 기능의 증거는
보존하며 현재 티켓에 미확보인 독립 결함·정답·후보 집합·운영 실행을 명시한다.

실제 API 경로의 원문 확인과 남은 계약
- 고정 프로젝트 commit 0bf2f4d1bfeb6605006d556957ef8c045d8f8ed8의 5파일을
  Git commit→tree→blob으로 증명하고 API 근거 13곳을 line/byte/span SHA로 연결했다.
- Ethereum.APIs가 eth namespace에 DownloaderAPI를 등록한다. subscription callback 분류와
  formatName을 거쳐 Syncing은 syncing 구독 이름에 연결된다. 요청 형태는 구독 가능한
  transport에서 eth_subscribe(["syncing"])이다. 일반 eth_syncing 호출과 구분한다.
- handler는 notifier를 context에 넣는다. Syncing은 unbuffered statuses를 등록하고,
  알림은 Notify로 넘기며 rpcSub.Err 또는 notifier.Closed에서 반환하면서 Unsubscribe한다.
- eth_unsubscribe([id])는 RPC 구독 err 채널을 닫고 RPC map에서 삭제한다. RPC 응답이
  downstream eventLoop의 uninstall 처리/확인 응답 또는 Unsubscribe 반환을 보장하지 않는다.
- 실제 Unsubscribe는 uninstall 요청 송신을 먼저 끝낸 뒤 status drain/확인을 기다린다.
  eventLoop는 status를 동기 송신하고 uninstall 수신 때 map 삭제 후 확인 채널을 닫는다.
- done 상태의 구독 등록/초기 false 송신, 알림과 RPC 종료의 동시 준비, Notify 활성화/버퍼/
  writeJSON 지연·오류, 다른 subscriber 정지, mux 종료로 loop가 끝난 뒤 확인 부재의 계약이
  미확정이다. 반환 상한·허용 순서·소유 정리·반환 후 status 미사용 조건을 독립 검토해야 한다.
- 소스 경로 확인은 실제 대상 transport/서비스 설정·API 도달성·실행 trace 증명이 아니다.
  이번 단계에서 API·host·node·network·모델 호출이나 target state/시계 변경을 하지 않았다.

티켓·후보·변이·독립성 분모
- 개발 티켓 SUB-EXIT-DRAFT-001 1개, AI 수정 후보 CAND-A/B 2개, 변이 2개,
  같은 가설의 시나리오 5개다. 승인 독립 티켓 0개이며 최소 2개는 여전히 미확보다.
- 후보 A는 요청 전 drain과 요청 후 확인 대기를 중첩 select로 나누고, B는 단일 select의
  송신 채널을 성공 후 nil로 만들어 요청 1회를 제한한다. 두 후보의 전체 API 계약 충족,
  종료/공정성·성능·메모리·유지보수 비교와 실제 적용 project tree는 미확인이다.
- 원본과 MUT-REINTRO는 같은 바이트다. 원본 복제·모드·스케줄·후보 수를 새 독립 결함으로
  세지 않는다. MUT-EARLY의 조기 반환 실패는 기존 AI 기준으로 관측된 범위만 보존한다.
- 기존 50관측은 5variant × 5상관 시나리오 × 일반/race 2모드다. 후보 A/B는 각 10/10의
  AI fixture 기준을 충족했다. ORIGINAL/재도입의 두 송신 대기 관측과 early-return 거부,
  rescue 전 완료/확인/삭제 및 시험 소유 goroutine 정리를 원래 분모/시점으로 유지했다.
- eventLoop/RPC notifier는 대역이다. 실제 API 전체 실행·installed 4-role 영수증은 없다.
  rescue 뒤 정리 성공을 rescue 전 정상 반환이나 프로젝트 수정 수용으로 바꾸지 않는다.

주/독립 도출 오라클 공백
- AI 주 기준은 모든 호출 반환·정확히 1 uninstall·삭제/확인·확인 전 반환 금지·owned cleanup이다.
  두 번째 wait graph는 같은 AI가 같은 source 가설에서 작성했다. 독립 derivation이 아니다.
- 독립 검토자가 티켓 조건으로 별도 oracle를 도출하고 primary 상수/helper 복사를 피해야 한다.
  실제 tier·source·RED carrier·head·driver·assertion identity·정상 대조군/변이를 사전 동결한다.
- timeout/빌드/launch 오류·미도달·다른 assertion·raw 변조·stale source·필수 단계 누락을
  결함 재현 RED 또는 정상 음성으로 세지 않는 판정과 분모가 필요하다.
- baseline 증상 RED/head GREEN·정상 GREEN·재도입/과적합 감지를 실제 API와 허용 계약에 묶고,
  종료 순서·반환 후 채널 미사용·동시 호출·반환 상한·rescue/cleanup의 독립 근거를 마련해야 한다.

수용 가능 후보 집합·선택 기준 공백
- CAND-A/B의 independent_acceptable_membership는 null이고 독립 승인 집합도 null이다.
  AI fixture 통과 후보로 채우거나 null을 승인된 빈 집합으로 바꾸지 않는다.
- 독립 검토자가 티켓별 후보 source commit/tree/diff·요구사항 pin과 포함/제외/unknown 사유를
  사전 동결해야 한다. correctness/정상 회귀/변이/실제 API/정리/필수 단계 hard gates와
  WARN/SKIPPED 허용 범위, 비교 axes/단위/방향/허용차·실행 adapter를 확정한다.
- 채택 consumer commit b7e78689676769e8536626e76eed7165d870e1ba의 9파일을 기존 채택
  SHA와 Git 증명으로 대조하고 oracle/선택/guard/4개 역할 계약 14곳을 연결했다.
- 구현은 후보를 격리 source에 materialize하고 oracle/regression/metrics를 실행하며,
  incomplete와 확정 부적격을 구분한다. all-bad는 REJECTED/선택 없음, 동률은 TIED,
  필수 측정·의견·실행 부족은 DEFERRED다. SELECTED는 필수 근거·일치 preference·단독 frontier를 요구한다.
- 이 엔진의 hard-eligible/Pareto/panel 판정에는 독립 gold 집합 membership 수용을 대체하는
  권한이 없다. 현재 티켓용 membership adapter/수용 receipt는 없다. 전역 최적성도 증명하지 않는다.
- simulation 완료 조건은 일부 WARN/SKIPPED를 허용하므로 정식 WI hard gates와 동일시하지 않는다.
  e2e oracle는 chainbench PASS를 요구한다. 실제 사용할 tier/필수 단계는 독립 동결한다.
- Analyzer의 준비→Planner의 후보 선택→Implementer의 선택 tree/RED carrier 적용→Evaluator의
  current HEAD 및 final V1 재검사→상태 guard 경로는 문서/코드에 존재한다. 역할 원문과
  Write|Edit hook 등록이 이번 티켓의 설치된 역할 실행/거부·재진입/handoff 영수증은 아니다.
