정의와 제외 범위
실제 shadow: 가장 가까이 보이는 바깥 로컬 변수와 다른 새 안쪽 변수 선언.
같은 블록의 x,y := ...에서 x 재사용은 새 shadow가 아니다. 파라미터와 함수 최상위
본문은 같은 scope이며, 형제 블록에만 있는 같은 이름도 서로를 가리지 않는다.
재대입은 알려진 로컬 식별자에 대한 =, 복합 대입, ++/--, range =, := 재사용이다.
필드/인덱스의 메모리 쓰기, package/import/universe 이름, 익명 함수 내부는 제외한다.
분기는 if·값 switch·type switch·select다. type switch guard는 case별 별도 바인딩이다.
같은 guard 원문 위치가 여러 case에 등장해도 독립 표본을 늘리지 않는다.
선언/재정의 후보는 같은 함수에 본문 변수 선언과 로컬 재대입이 모두 있는 보수적 제안이다.
이를 정식 구문 정의로 채택할지는 검토가 필요하다.
소스 전체 프로젝트의 타입 검사를 수행하지 않았다. 원문은 파싱만 했고 실행하지 않았다.
변수 use 순서·alias·경로 실현 가능성·완전한 may-reach/제어 의존 edge는 산출하지 않는다.

검증
Go 1.26.9, 표준 라이브러리만 쓰는 임시 모듈로 build/fmt/vet/lint 4건 통과.
개발 대조군 22개를 Go 표준 go/types의 실제 선언 바인딩과 대조했다.
형제/중첩 블록, 혼합 :=, 파라미터/결과/receiver 재사용, if/for/range,
switch/type-switch/select scope, blank, 중간 type 이름, initializer, closure 제외를 포함한다.
일반/race 각각 22개로 총 44개 관측 통과. AI가 작성한 개발 대조군이며 독립 gold가 아니다.
검증기는 실행 가능한 코드를 packet에서 불러오지 않고 신뢰하는 live analyzer만 사용한다.
원문 40개를 오프라인에서 재파싱해 원자료와 완전히 같은 관측인지 확인한다.
재파싱에는 설치된 호환 Go도 사용할 수 있지만, 보존한 본 시험은 Go 1.26.9이다.
