signature 범위 4개를 분리한 이유
SRC-024 deliver — eth/downloader/queue.go:865~866
validate func(index int, header *types.Header) error
reconstruct func(index int, result *fetchResult)
위 index/header/index/result는 함수형 내부 파라미터 선언이다. 바깥 deliver의 본문 변수와 다르다.
부분 Go 타입 정보는 이 위치들도 변수로 보고하지만 기존 본문 lexical census에는 속하지 않는다.
원자료를 삭제하지 않고 quarantined_non_body_signature_scope로 표시했다.
실제 함수 파라미터는 선언 위치 대조가 먼저 성립하므로 signature 앞에 있어도 잘못 격리하지 않는다.
모호한 후보가 여러 개면 첫 번째를 고르지 않고 모두 보존한다. 미일치는 임의로 본문 변수로 만들지 않는다.

관측한 것과 계산하지 않은 것
Go 표준 타입 정보의 로컬 선언 위치와 별도 lexical census를 대조했다.
return/break/continue 등은 구문상 소유 함수·loop·switch를 관측했다.
실행 가능한 CFG, reaching definitions, 정상 종료 postdominator, data/control edge는 계산하지 않았다.
구문상 이동 대상이 확인됐어도 runtime 도달성·종료 보장·제어 의존성은 미확정이다.
scalar/reference/aggregate kind와 메모리 alias·외부 호출·채널·동시 실행 효과는 확정하지 않는다.
range_binding_unsupported는 현재 backend의 범위 제한이며 함수 전체가 분석 불가라는 뜻은 아니다.
범위 밖 사실을 자동 negative edge로 바꾸지 않고 관측 자료와 지원 제한을 분리한다.
data_edges/control_edges/quality_scores는 null이며 모든 독립 승인·gold·scoring은 false/미작성이다.
