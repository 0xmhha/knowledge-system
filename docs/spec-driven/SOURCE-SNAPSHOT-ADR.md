# ADR: 소스 스냅샷과 인용 신원 v0 (설계 검증 대기)

작성일: 2026-09-30 · 상태: **제안, A3/A4 구현 전 기술 검증 필요** · 관련 계약: INV-01/02/03/06, FR-09/10, S-07/08/09

## 문제

현재 `cks setup`은 깨끗한 `committed` 입력만 받아 Git HEAD를 CKG/CKV 인용에 기록한다. 이는 안전한 제한이다. 더러운 작업 트리를 그대로 읽으면 두 엔진이 서로 다른 시점의 파일을 볼 수 있고, 같은 HEAD의 수정·신규 파일은 같은 버전으로 오인된다. 현재 CKV 매니페스트에는 안정 `project_id`/`dataset_id`/`snapshot_id`가 없으며 의미 투영은 자체 프로젝트/데이터셋 ID를 갖는다. 기존 인용 소비자는 커밋·경로·줄을 사용한다.

## 결정할 계약

| 좌표 | 정의 | 필수 불변식 |
|---|---|---|
| `project_id` | 한 번 발급하거나 명시해 설정에 보존하는 안정 ID. 이름·로컬 절대 경로와 별개 | 같은 ID를 다른 프로젝트에 재사용하면 거부. 이동/복제 뒤에도 ID 유지. |
| `source_commit` | 캡처 시작의 전체 HEAD SHA | Git 이력의 기준점이며 작업 트리 바이트의 유일한 신원이 아니다. |
| `file_manifest_digest` | 선별된 저장소 상대 POSIX 경로, 파일 종류, SHA-256, 제외 정책 버전을 순서대로 직렬화한 SHA-256 | 수정·신규 파일과 정책 변경으로 값이 바뀐다. 정렬/정규화/UTF-8 경로 규칙은 골든으로 고정. |
| `snapshot_id` | `project_id`, `source_mode`, `source_commit`, `file_manifest_digest`를 도메인 분리된 정규 형식으로 해시 | 같은 HEAD의 다른 바이트가 같은 ID가 될 수 없다. |
| `dataset_id` | `snapshot_id`, 빌드 전 고정한 그래프/벡터/의미 입력 파일·정책 다이제스트 및 스키마, 임베딩 정체성을 해시. 출력 다이제스트는 제외 | 같은 원천의 다른 모델/정책/스키마는 다른 데이터셋. 순환 신원 없이 빌드 전에 계산되며 사용자 버전 별칭과 다르다. |

`committed`와 `working-tree`는 서로 다른 `source_mode`를 갖는다. 청결한 HEAD를 작업 트리 모드로 캡처해도 원문 파일 집합은 같지만 모드는 다른 신원이며, 검색 결과의 내용과 줄은 일치해야 한다. V1 인용의 `commit_hash` 필드는 계속 유지하고 추가 필드 `snapshot_id`, `content_digest`, `project_id`, `dataset_id`는 선택형으로 추가한다. **working-tree 인용에서는 새 필드가 모두 필수**다. 구 소비자가 새 필드를 무시해 작업 트리 인용을 HEAD 원문으로 오해할 수 있으므로, 호환 검증 전에는 작업 트리 데이터셋을 기존 MCP 인용 형식으로 서빙하지 않는다. 새 클라이언트가 지원을 선언하거나 MCP 프로토콜 버전을 협상하도록 설계한다.

## 캡처와 승격 절차

1. 소스 루트의 실경로와 Git 공통 디렉터리를 확인한다. CKG/CKV가 실제 선택할 수 있는 파일 경로 목록을 각 엔진의 탐지 규칙으로 계산한다. 정책이 다른 항목은 목록에 포함한 뒤 엔진별 예상 입력 여부를 표시한다. 비밀 경로, 외부로 나가는 심볼릭 링크, 디바이스/소켓, 읽기 불가 파일은 명시적으로 제외하거나 오류로 처리하며 `doctor`에 개수만 노출한다.
2. 파일 목록과 각 원문 SHA-256을 읽고 후보의 별도 staging 디렉터리에 저장한다. 복사 직후 원본/사본의 크기·해시를 확인한다. 하드링크는 원본의 추후 쓰기로 바뀔 수 있으므로 사용하지 않는다. staging 위치는 활성 데이터셋 밖이다. 파일 권한은 빌더에 필요한 읽기만 남긴다.
3. CKG의 Git 이력 경로가 staged 바이트와 동일한 기준 HEAD를 볼 수 있도록 임시 Git worktree + 오버레이를 **우선 기술 검증안**으로 사용한다. 빌드는 임시 worktree만 읽고 원본 작업 트리를 읽지 않는다. 엔진에는 `build_root`(임시 worktree)와 `logical_source_root`(설정에 저장한 프로젝트 위치), `snapshot_id`를 별도로 전달해야 한다. 경로 정렬·인용은 저장소 상대 경로를 쓰고, 공개 매니페스트에 임시 `build_root`를 남기지 않는다. CKG가 이력·AST를 모두 staged 소스에서 읽는지, CKV/CKG가 저장한 절대 경로와 `canonical_id`가 임시 위치에 종속되지 않는지 테스트한다. 검증이 안 되면 이 모드는 출시하지 않고 캡처 어댑터를 재설계한다.
4. CKV/CKG와 의미 투영의 실제 입력 경로/해시를 사전 목록과 대조한다. 원본 작업 트리는 캡처 완료 후 바뀌어도 **캡처한 후보의 내용은 바뀌지 않는다**. 단, 캡처 도중 바뀐 파일은 실패시킨다. 후보의 저장 바이트와 각 출력 매니페스트를 빌드 종료 후 다시 검증한다.
5. 후보에 원문 파일을 콘텐츠 주소로 보관한다. 근거 검증 API는 `committed`에서는 Git 객체, `working-tree`에서는 보관본을 선택해 같은 저장소 상대 경로·줄 범위·SHA-256 계약을 제공한다. 작업 트리 인용을 현재 소스 경로나 Git HEAD의 파일로 재해석하지 않는다. 보관본이 없거나 해시가 다르면 `source_missing`/`snapshot_mismatch`를 반환한다. 공간 회수는 인용 보존 정책과 함께 별도 명령으로 수행하고 활성/롤백 가능 버전의 원문은 지우지 않는다.
6. 그래프·벡터·의미 매니페스트의 모든 ID, 실제 파일 목록, 모델 신원을 검사한 후에만 `current`를 원자 전환한다. 실패/취소/프로세스 종료 중에는 이전 `current`와 그 원문 보관본을 유지한다. 승격 직후 질의/롤백도 같은 좌표를 재검증한다.

## 기존 데이터와 이전

기존 `committed` 데이터셋의 빈 `project_id`/`snapshot_id`는 `legacy_unpinned`으로 읽고 원래 커밋 인용만 제공한다. 다른 프로젝트/작업 트리와 결합하거나 의미 승격할 때 자동 보충하지 않는다. 사용자는 새 `cks init` 설정과 전체 재색인으로 v2 ID를 얻는다. 마이그레이션은 옛 DB 파일을 제자리에서 재해석하지 않는다. 새/옛 EvidencePack의 JSON 골든과 소비자 회귀가 통과해야 새 필드를 공개한다.

## 기술 검증과 실패 오라클

| 실험 | 통과 조건 |
|---|---|
| 같은 HEAD에서 추적 파일 수정→신규 파일 추가→다시 수정 | 세 `file_manifest_digest`/`snapshot_id`가 다르고 각 원문 인용이 보관본의 해당 바이트/줄을 가리킨다. |
| 캡처 중 파일 변경·삭제·심볼릭 링크 교체 | 캡처 또는 해시 재검증이 실패하고 `current` 불변. |
| CKG 이력 포함 작은 Git 픽스처 | staged AST는 수정 바이트를 인덱싱하지만 이력 기준은 원래 HEAD이고 임시 절대 경로가 공개 팩에 새지 않는다. |
| 후보 그래프 성공/벡터 실패·의미 불일치·모델 교체 | 승격 거부, 기존 핸들/롤백 가능 버전 유지. |
| 동일 이름 두 저장소와 동일 commit SHA 테스트 데이터 | `project_id`가 다르면 조인/질의/캐시 키 분리. |
| 보관본 손상/삭제, 구버전 매니페스트 | 조용한 HEAD 재해석 금지. 명시 오류 또는 제한된 legacy 읽기. |
| 외부로 나가는 링크/비밀 경로/권한 실패 | 경로·원문 누출 없이 거부 또는 기록된 제외. |

### 2026-09-30 CKG 기술 검증 1차 결과

`/private/tmp/ks-snapshot-spike.O1uiWX`의 작은 Go 저장소에서 한 커밋을 만들고 `git worktree add --detach`로 분기한 뒤 함수 `Before`를 `AfterWorkingTree`로 바꿨다. 현재 `ckg build --src <staged> --lang go`는 수정된 `AfterWorkingTree` AST 노드를 만들고 동시에 원래 HEAD의 temporal 노드/엣지를 생성했다. 노드의 `file_path`는 `main.go`로 상대 경로였다. 반면 CKG 출력 매니페스트의 `src_root`는 임시 staged 절대 경로였다. **결론:** Git 이력과 수정 AST의 동시 수집은 작은 픽스처에서 가능하다. 임시 절대 경로를 정렬/매니페스트/인용에 남기지 않는 인터페이스 변경과 다른 언어·큰 저장소·worktree 제거 뒤 재조회 검증은 남아 있다. 이 결과만으로 ADR을 승인하지 않는다.

## 남은 설계 결정

이 ADR은 요구되는 **관찰 가능 계약**을 고정하지만 임시 worktree의 Git 이력 접근과 원문 보관 형식은 아직 실험 전이다. 특히 CKG가 Git worktree의 수정 파일을 이력 처리할 때 어떻게 취급하는지, 별도 머신으로 이동한 데이터셋이 원본 Git 저장소 없이 모든 인용을 재현할 수 있는지 확인해야 한다. 두 실험 결과와 공개 MCP 소비자 호환 결과가 나오기 전에는 상태를 `Accepted`로 바꾸지 않는다.
