# D5 산업·조직 지식 확장: 승인된 설계 결정

상태: **D5-01–07 사용자 설계 승인, D5 설계 게이트 폐쇄** · 2026-10-01. 사용자가 승인한 D1 공통 20개는 바꾸지 않는다. 이 문서는 [상세 기술 계약](./DOMAIN-PACK-CONTRACT-V1.md)을 제품 결정 단위로 정리한 승인 기록이다. 설계 승인은 특정 산업 정책이나 코드 관계를 `verified`로 만드는 승인이 아니며, A 단계 구현 또는 B/C 품질 승인을 뜻하지 않는다.

## 1. 고정 코어와 확장 영역

```text
모든 프로젝트: D1 공통 20개 타입 + CKV 원문 검색 + 지원 언어의 CKG AST 그래프
선택 설치: 범용 설계 결정 팩 → 산업/기술 팩 → 프로젝트·조직 오버레이
실제 지식: 정책·ADR·요구·관계의 원문과 사람의 검토 기록
```

- 공통 20개는 `project`, `dataset`, `source-snapshot`, `code-symbol`, `concept`, `requirement`, `evidence-pack`, `patch-attempt`, `criterion-decision` 등을 포함하는 **시스템 메타모델**이다. 블록체인, 의료, 제조의 업무 개념 20개라는 뜻이 아니다. 정확한 목록과 쓰임은 [D1 20개 용도](./ONTOLOGY-20-USAGE.md)에 있다.
- 확장 팩에는 산업 객체·행위·규칙의 **타입 정의**를 둔다. 예를 들어 `industry.blockchain#transaction`, `platform.evm#smart-contract`는 선택 설치된 개념 타입이다. 특정 회사의 전송 한도나 승인 규칙은 프로젝트 오버레이의 **지식 인스턴스**여야 한다.
- `engineering.decisions#design-decision`은 설계 선택과 이유를, 공통 `criterion-decision`은 특정 변경의 수용 기준에 대한 **사람의 판정**을 기록한다. 공통 `policy`는 CKS의 접근·색인 규칙이고, 업무 규칙은 확장 `business-policy`로 분리한다.
- 새로운 산업 개념 수는 20개로 제한하지 않는다. 코어 ID/뜻을 덮어쓸 수 없고 확장 키 `(pack_id, local_id)`로 식별한다. 개념의 정의·포함/제외 범위·한영 용어를 문장으로 작성하되 용어가 같다는 이유만으로 다른 팩의 개념을 병합하지 않는다. 이는 SKOS의 개념·다국어 라벨 구분을 참고한 **프로젝트 설계**이지 RDF/SKOS 런타임 준수 주장이 아니다. [W3C SKOS](https://www.w3.org/TR/skos-reference/).

## 3. 지식이 코딩에 도달하는 경로

예시 질문: “전송 승인 조건을 바꿀 때 어떤 코드와 테스트를 수정해야 하며 왜 그렇게 구현됐나?”

1. CKV는 정책/ADR/스펙의 문장과 코드 청크를, CKG는 실제 AST 심볼·호출·테스트를 같은 소스 스냅샷에서 찾는다.
2. CKS는 선택 팩의 `transaction`/`transfer` 등의 **복수 개념 후보**를 검토한다. 미등록 표현도 원문 검색 경로를 유지한다.
3. 검토된 프로젝트 정책 `BR-17`과 설계 결정 `ADR-04`가 있으면 각 원문과 적용 시점을 확인하고 정책→결정→요구→심볼→테스트 경로를 붙인다. 없다면 “왜”는 `unknown`이다.
4. 코딩 도구에는 `현재 구현`, `요구되는 동작`, `설계 이유`, `제약`, `근거`, `미확인/충돌`을 별도 필드와 인용으로 제공한다. 정책/ADR 원문은 지식 **데이터**이지 도구 실행 명령이 아니다.
5. 패치와 실행은 공통 `patch-attempt`/`test-run`으로 기록하고, 수용 기준의 의미 충족은 별도 `criterion-decision`으로 사람이 판정한다. 테스트 성공만으로 승인하지 않는다.

## 4. D5 설계 게이트 폐쇄 근거

아래는 **설계 완료** 조건이며 모두 충족됐다. A5/A6/A7 구현 통과나 B/C 실모델 성능 합격을 뜻하지 않는다.

1. 사용자가 D5-02–05의 신원·출처·타입·질의/폴백 계약과 위 실패 오라클을 제안대로 승인했다.
2. 사용자가 D5-06 파일럿(`knowledge-system` 자체 정책/ADR, 선택형 블록체인 구조 fixture, 비블록체인 격리 대조)과 D5-07 입력 위치(`.cks/knowledge` 및 등록 로컬 루트)·기본 검토 역할(프로젝트 소유자 1명, 상향 가능)을 제안대로 승인했다. 실제 산업 프로젝트의 정책 소유자·실모델 정답 승인자는 B0에서 별도로 기록한다.
3. [종단 간 설계](./END-TO-END-DESIGN.md)의 데이터셋/원문 좌표와 기본 검색, [공개 v2 계약](./PUBLIC-CONTRACT-V2.md)의 선택형 `semantic.knowledge_context`·v1 호환, [WBS v2](./DELIVERY-PLAN-V2.md)의 A5.4/A5.5/A6/A7.1/A8/B0/B1 선행·실패 조건을 대조했다. 공통 20개 재정의, v1 응답 변경, 미검토 지식의 확정 사용을 요구하는 충돌은 없다.
4. 사용자 승인일은 2026-10-01, 결정자는 프로젝트 사용자다. D5-02–07 권고안에서 변경한 항목은 없다. 설계 결정 보류 사항은 없으며, 프로젝트별 실제 정책 인스턴스의 검토와 B0 질문 정답·임계치 승인은 별개다. 이 기록과 [`DESIGN-GATES-EVIDENCE.md`](./DESIGN-GATES-EVIDENCE.md)를 설계 게이트 증거로 사용한다.

승인된 설계 기준선은 인스턴스별 정책 내용·검토자 신원·실모델 질문 정답을 미리 만들어내지 않는다. 이들은 이후 각 프로젝트와 B0의 별도 입력이다.
