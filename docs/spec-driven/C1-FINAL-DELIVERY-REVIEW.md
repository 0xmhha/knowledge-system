# 최종 지원·제한·종료 범위 검토

2026-10-06 · C1-07 보고 완료·명시적 잔여 포함. [FINAL 평가](./C1-APPROVED-FINAL-REPORT.md), [최신 패키지](./C1-FINAL-PACKAGE-VALIDATION.md), [사람 출력 검토](./B1-APPROVED-OUTPUT-CLAIM-REVIEW.md), [운영 검토표](./C1-OPERATIONS-REVIEW.md)가 근거다. 현재 **26/30 작업 완료·4개 미완료**, 운영 출시 보류·온톨로지 기본 disabled다. 전체 완료를 기록하지 않았다.

Go 없는 런타임의 empty-Go/Python은 문서 기반 degraded가 정상이며 TypeScript는 분석 가능 범위다. Go 소스 분석을 지원하려면 Go 분석 도구 체인을 별도로 제공해야 한다. mock은 모델 검색 품질을 판정하지 않는다. 플랫폼별 Go 도구 체인·합성 source commit·binary SHA는 원장에 각각 남겼다.

## 알려진 제한과 최종 기술 판정

- 승인 FINAL 4,800회 중 POLICY-03 정상 팩을 반환하지 못한 240회가 있다. 양성 정적 6문항 중 기대 근거를 찾은 문항은 1개, 양성 Recall 0.1667/MRR 0.0833이다. 실패를 제외한 성공률로 바꾸지 않는다.
- 두 기권 문항의 strict no-citation 조건은 실패했다. 사람의 답변 기권 판단은 별도 HC-09/10 검토를 기다린다. 제품은 LLM 생성 답변을 반환하지 않는다.
- 중요 질문군의 독립 최종 표본은 각각 10개 미만이다. 승인 규칙에 따라 inconclusive이며 기본 활성/출시 근거로 쓰지 않는다. 반복·언어·상태 변형으로 독립 표본을 늘리지 않는다.
- 지연은 정적/동적/pooled 및 같은 팩 축별 비교를 모두 보존했다. 일부 dynamic p95 비율이 1.25를 넘는다. 가장 유리한 pooled 수치만 골라 통과시키지 않는다. 사람 검토 시간·비용은 미측정이다.
- 정상 팩의 source/좌표/해시 검증과 선택적 backend 오류를 구분한다. 최신 대규모60의 neighbors 오류360·별도RSS2의12·Linux 실제SDK6의6을 기록했다.
- 32,000바이트 본문 상한은 유지했다. FINAL 결과에 맞춰 상한·질문·gold·K·제품 소스를 수정하지 않았다. 개선하려면 새 개발 버전과 결과를 보기 전에 검토한 별도 최종 입력이 필요하다.
- 시험 scope의 Ed25519 검증기는 운영 키 권한·유효 기간·온라인 폐기·운영 출시 승인을 증명하지 않는다. 시험 키를 운영 키로 승격하지 않았다. 원문 고지 수집/SHA 검증은 법무 적합성 판정과 별개다.

따라서 **현재 품질 판정은 fail, 중요 그룹은 inconclusive, 운영 출시는 보류**다. 구현의 온톨로지 opt-in/disabled 기본값을 유지했다. 공식 stage 원장 0/4는 사람/운영 종료가 남은 상태이며 “평가하지 않음”이나 “실패를 숨김”을 뜻하지 않는다. 기술 결과는 수치·오류를 포함해 확정했다.

| C1-05 | 시험 서명·독립 신뢰 검증·변조 회귀·고지/원래 native 출처 감사 자료 | 운영 역할/키/독립 신뢰/보관/폐기/적합성 결정 또는 시험 deliverable 범위로 한정하는 명시적 결정 |


기존 비동기 검토 요청의 **HC-01–08/검토 비용**과 **시험 preview로 종료할지·실제 운영 출시까지 요구할지** 답변은 아직 없다. FINAL 수집 후 추가한 HC-09–11은 별도 요청했다. 입력①–⑤ 승인을 이 판정으로 재사용하지 않는다. 미측정 비용을 0으로 채우거나 실제 운영 역할·키·법적 적합성을 도구가 대신 승인하지 않는다.

시험 preview를 최종 deliverable로 선택하면 품질 fail/disabled와 미확인 환경·운영 제외를 명시하여 종료할 수 있다. 운영 출시를 요구하면 OP-01–08의 실제 책임/키·신뢰 경로/권한·적합성 판정, 네이티브 AMD64 등 요구한 환경·운영 backup/failover 증거가 추가로 필요하다. scope 선택은 품질 합격이나 원격 배포/새 Git push 승인이 아니다. 개인 키 본문을 제출할 필요는 없다.

## 보고 종료와 전체 목표 종료의 구분

B1-06은 [비용 보고](./B1-COST-REPORT.md)에 실측과 미측정 값을 연결해 완료했다. 미측정 비용의 사실 기록에는 별도 승인이 필요하지 않으며 비용0이나 실제 검토 승인으로 바꾸지 않았다. C1-07은 원래 조건의 “명시적 잔여 범위”에 따라 이 보고와 출시보류 판정을 완료했다. 선행 C1-05와 HC 미완료를 표에 드러냈으며 운영배포/키/법적 적합성/최종 scope의 사람 결정을 대신하지 않는다.

따라서 남은전체는 B1-04·07·08, C1-05의4개다. 실제 scope 선택은 C1-05 잔여다. 이 보고를 전체30목표완료·실제운영지원승인으로 읽지 않는다. 새로운 결과를 만들거나 임계치/완료조건을 변경하지 않고 기존 증거·미측정·미완료 사실에 맞춰 보고 상태를 바로잡았다.
