# 2026-11-20 연구일지 04: 정답 라벨 수신과 출발 심볼 검사

## 받은 것

다른 컴퓨터의 knowledge-system 세션이 두 번째 답을 보냈다.

- 11문항의 기준 커밋과 수정 커밋. 수정 커밋의 부모가 기준 커밋과 같은지 go-stablenet에서 `git rev-parse`로
  확인했다(11/11). 기준 커밋 11개는 모두 다르다. 몇몇 수정 커밋은 다음 문항의 기준 커밋이다.
- `oracle.jsonl`의 11행을 줄인 형태. [data/oracle-relayed.json](../oracle-seed-offline/data/oracle-relayed.json)에
  옮겨 적었다. 줄 번호는 기준 커밋 기준이다. core 표시는 모델이 붙였고 사람이 수용하지 않았다.
- `questions.jsonl`과 `oracle.jsonl`의 sha256 전체 값. 파일을 받으면 이 값으로 대조한다.
- 하네스는 질문 문장을 그대로 `claude -p`에 넘긴다. 위에 붙는 글은 `--append-system-prompt`의 지시문과 arm별
  안내문이다.
- 재생 스크립트(e1offline, rerank, offline2)의 위치와 실행법. 셋 다 기록된 에이전트 호출을 다시 돌린다.
  이 실험은 고정한 출발 심볼에서 시작하므로 실행기를 새로 쓴다(TASKS 7a).

## 출발 심볼이 기준 커밋에 있는가

| 결과 | 문항 |
|---|---|
| 모두 있음 | sym-55, 58, 63, 67, 69, 70, 73, 74, 75, 77 |
| 모두 없음 | sym-56 (`splitAndTrim`, `initializeAnzeonGenesis`) |

- sym-67의 `PrecompiledContractsAnzeon`은 첫 자동 검사에서 없다고 나왔다. `var` 선언이라 검사식이 놓쳤고,
  단어 검색으로 있음을 확인했다.
- sym-56의 기준 커밋은 2026-02-11이다. 심볼을 찾은 트리 `8d7930a4`는 2026-03-05라 이 수정보다 나중 코드다.
  고른 두 심볼은 수정 커밋이 만든 코드일 수 있다. 그러면 정답이 샌 것이다. 정한 규칙대로 대체하지 않고 뺐다.
  sym-56은 blind 출발 심볼이 없는 문항이 된다.

## 배운 것

- 출발 심볼은 각 문항의 기준 커밋 트리에서 골라야 한다. 기준 커밋을 모른 채 다른 트리에서 고르면, 그 트리가 수정 뒤의
  코드일 때 정답이 샐 수 있다. 2단계에서 문항을 늘릴 때는 기준 커밋 트리만 보여 주고 고른다.
