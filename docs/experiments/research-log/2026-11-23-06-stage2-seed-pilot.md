# 2026-11-23 연구일지 06: 2단계 출발 심볼 시험

세션: second-brain-eval-kit에서 연 Claude 세션. 작업 13을 시작했다가 멈췄다.

## 정한 것

- 사용자가 추천 B를 골랐다. 문항 작성 에이전트(diff를 봄)와 출발 심볼 에이전트(증상만 봄)를 나눈다.
- 작성 에이전트는 5문항씩 묶어 4개, 예비 2문항에 1개를 썼다. 출발 심볼 에이전트는 문항마다 하나씩 띄웠다.
  커밋 기록이 한 줄이라 나중 커밋의 트리에는 앞선 문항의 수정이 들어 있기 때문이다.

## 한 것

- 후보 앞 20개 중 2개(테스트와 퍼즈 파일만 바꾼 수정)를 작성 에이전트가 제외했고, 예비 2개를 작성했다.
  공개할 때의 문제로 1개를 더 빼서 증상 문장은 19개다([data/questions-symptom-stage2.json](../oracle-seed-offline/data/questions-symptom-stage2.json), 출발 심볼을 고르기 전에 커밋 `ecb9891c`).
- 라벨 초안의 core는 모두 수정 커밋이 바꾼 위치였다(diff hunk와 겹침 확인). 라벨은 아직 저장소에 넣지 않았다.
- 출발 심볼 에이전트 10개를 돌렸다. 나머지 9개는 띄우지 않았다.

## 결과

- **10문항 모두에서 core 전부(문항당 1개)가 출발 심볼에 들어 있었다**([data/stage2-seed-pilot.json](../oracle-seed-offline/data/stage2-seed-pilot.json)).
  core가 출발 심볼이면 두 방식 모두 0위라서 강제 무승부다. 이 묶음으로는 결정 A를 가를 수 없다. grep과 graph는 돌리지 않았다.
- 에이전트는 도구를 4~8번 부르고(결과 전달 포함) 14~30초 만에 골랐다. 함수 본문을 읽고 원인을 찾은 기록이 있다(s2-01).
- 1단계 blind에서는 core 20개 중 5개가 출발 심볼이었다.

## 원인 후보 (확인 안 됨)

- **문항이 쉽다.** 바꾼 파일이 1개인 수정부터 골랐고, 모두 core가 1개다.
- **증상이 구체적이다.** 작성 에이전트가 diff를 보고 썼으므로 위치를 좁혀 주는 조건이 많다.
- **지침이 느슨하다.** 본문을 읽지 말라고 하지 않았다. 에이전트는 처음 찾아볼 심볼이 아니라 원인을 골랐다.
- **모델이 업스트림 수정을 안다.** 업스트림 go-ethereum에서 온 수정이 섞여 있을 수 있다. 세지 않았다.
- **정답이 샜다.** 도구 호출 기록에서는 흔적을 찾지 못했다. 검사는 절대 경로와 `..`만 봤다.
