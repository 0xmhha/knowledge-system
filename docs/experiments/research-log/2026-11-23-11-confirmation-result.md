# 2026-11-23 연구일지 11: 양방향 2 hop 걷기의 확인 결과

세션: second-brain-eval-kit에서 연 Claude 세션. DESIGN 12장대로 돌렸다. 걷기와 순위(`dc1e9600`), 빌드 변경(`888608f7`)은 실행 전에 고정했다.

## 문항

- 2022~2024년 수정 47개 중 그래프가 만들어진 것은 33개다. 8개는 Go 버전이 1.17보다 낮아 범위가 안 만들어졌고, 6개는 ckg 빌드가 멈췄다.
- 바뀐 선언이 2개 이상이고 다른 파일에 정답이 있는 문항은 27개다. 두 번 돌려 출력이 같았다. 값은 출발점별 원자료로 셌다.

## 주 판정 (다른 파일 정답, 새 걷기 대 grep)

- **판정하지 않는다.** 새 걷기 5승, grep 2승, 무승부 20이다. 갈린 문항이 7개라 정해 둔 12개에 못 미친다(부호 검정 p = 0.453).
- 무승부 20개 중 18개는 두 방식 다 10위 안에 정답이 없는 문항이다.

| 다른 파일 정답, 문항 27개 평균 | grep | 출하 graph | 새 걷기(all7/log) |
|---|---|---|---|
| recall@10 | 0.037 | 0.095 | 0.110 |
| 도달률 | 0.175 | 0.129 | 0.435 |

## 보조 (판정에 쓰지 않음)

- 다른 파일 정답에서 새 걷기 대 출하 graph: 5승 8패 14무(p = 0.581). 출하 graph 대 grep: 8승 2패 17무(p = 0.109).
- 같은 파일까지 합친 정답에서 새 걷기 대 grep: 18승 0패 9무(p = 7.63e-06). 새 걷기 대 같은 파일 방식: 9승 6패 12무(p = 0.607).
  평균 recall@10은 새 걷기 0.263, 같은 파일 0.184, 출하 graph 0.143, grep 0.074다.

## 읽는 법

- **고르는 데 쓴 자료의 0.2561은 새 문항에서 0.110이 됐다.** 문항과 그래프 설정이 다르므로 두 값은 같은 잣대가 아니다.
  다만 고르는 자료의 값이 새 문항에서 이어지지 않았다는 것은 말할 수 있다.
- **닿기는 하지만 10위 안에 들지 못한다.** 새 걷기의 도달률은 grep의 약 2.5배인데 recall@10은 0.110이다. 이 걷기에서 약한 곳은 순위다.
  연구일지 08에서 철회한 해석("약한 곳은 순위")은 출하 graph와 grep에 관한 것이었다. 새 걷기에는 따로 적용된다.
- 같은 파일까지 합친 18대 0은 grep보다 낫다는 뜻이지만, 같은 파일을 가까운 순서로 놓기만 한 방식보다 낫다고는 할 수 없다.

## 한계

- 같은 코드 계열의 수정이다. 다른 프로젝트에서 통하는지는 모른다.
- 그래프는 모듈 없이 만들었다. 쓴 간선은 커밋 하나에서 98.8% 이상 남는 것을 확인했다. 출하 graph가 쓰는 implements에는 없던 간선이 생긴다.
- 정답에는 정리 수정이 섞인다. 27문항 중 18문항에서 두 방식 모두 0이라 차이를 가릴 여지가 작았다.
