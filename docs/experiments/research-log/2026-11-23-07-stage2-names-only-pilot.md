# 2026-11-23 연구일지 07: 이름 목록만 보고 고른 출발 심볼

세션: second-brain-eval-kit에서 연 Claude 세션. 작업 13을 다시 멈췄다.

## 정한 것

- 사용자가 추천 A를 골랐다. 출발 심볼 에이전트에게 코드 대신 선언 이름 목록만 주고, 바꾼 파일이 2~5개인 수정에서 문항을
  다시 뽑는다. 먼저 5문항을 시험한다.
- 중단선은 실행 전에 정했다(`bb28dbfb`): 5문항 중 core가 모두 출발 심볼인 문항이 2개 이하일 때만 넓힌다.
- 증상과 라벨은 저장소에 넣지 않고 sha256만 커밋한다(`f8fdab65`). 일부 문항의 증상이 공개하기 어려운 내용이다.

## 빌드 설정의 한계

- 2025년 초의 기준 커밋에는 시스템 컨트랙트가 없어 1단계와 같은 범위 설정으로 그래프를 만들 수 없다. 설정은 바꾸지 않았다.
- 후보 69개(바뀐 줄 3줄 이상) 중 36개, 파일 2~5개인 27개 중 13개만 빌드된다. 문항을 60~100개로 늘리는 목표는
  이 저장소와 이 설정으로는 채울 수 없다.
- p2-02, p2-06, p2-07을 이 이유로 건너뛰고 p2-08을 썼다. 고정한 교체 규칙에 없던 일이며 출발 심볼을 고르기 전에 정했다.

## 결과

- **5문항 모두에서 core 전부(9/9)가 출발 심볼이었다**([data/stage2-pilot2-result.json](../oracle-seed-offline/data/stage2-pilot2-result.json)).
  중단선을 넘었으므로 넓히지 않는다. grep과 graph는 돌리지 않았다.
- 에이전트는 이름 목록을 1~2번 grep하고 11~15초 만에 골랐다. 명령 기록에 자기 목록 밖을 연 흔적은 없다.
- 앞 시험(파일 1개, 코드를 읽음)까지 합치면 15문항에서 core 19개가 모두 출발 심볼이었다.

## 이 결과로 할 수 있는 말과 없는 말

- **할 수 있는 말:** 이 15문항에서는 증상 문장과 이름 목록만으로 정답에 닿았다. 그래서 이 문항으로는 grep과 graph를 가를 수 없다.
- **없는 말:** graph가 필요 없다는 말은 할 수 없다. 이 증상은 diff를 본 에이전트가 썼으므로 실제 사용자 보고보다 쉬울 수 있다.
  라벨의 core도 같은 모델 계열이 골랐다. 1단계 blind에서는 core 20개 중 5개가 출발 심볼이었다.
- **모델 기억:** 5문항의 수정 날짜는 2026-06-09부터 2026-10-13까지다. 4개는 모델 지식 기준일(2026년 6월) 뒤다.
  그래도 저장소의 다른 코드는 알고 있을 수 있다. 확인하지 않았다.

## 다음 세션이 알아야 할 것

- 증상에서 출발 심볼을 고르는 방식은 2단계에서 두 번 연속 실패했다. 같은 방식의 세 번째 시도는 하지 않는다.
- 토큰: 작성 에이전트 약 20만, 출발 심볼 에이전트 5개 약 50만(완료 알림의 값).
