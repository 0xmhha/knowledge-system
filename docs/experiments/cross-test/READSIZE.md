# 동작하는 graph의 읽은 양 (4문항)

작성 2026-11-24. 실행 전에 고정한다. grep 조건의 기준값이 이미 있는 문항 중 많이 읽은 것을 쓴다.

## 1. 가를 결정

grep 조건에서 이미 읽은 글자: go-wemix#209 118,182, go-wemix#186 83,052, go-wemix#205 72,124, `core.Genesis.Config`(영향 범위) 112,980.

| 결과 | 행동 |
|---|---|
| 4문항 중 3문항 이상에서 그래프 호출이 실제 응답을 받지 못했다 | 장비 문제다. 고치고 다시 점검한다 |
| 읽은 글자가 grep의 60% 이하인 문항이 3개 이상이고, 정답 재현율이 grep보다 낮은 문항이 없다 | 여러 번 반복한 시험을 제안한다(예: 문항 4개, 조건 2개, 3번) |
| 그 밖 | 줄어든다는 근거가 없다. 연구를 마감한다 |

조건마다 한 번이고 같은 문항의 grep 값도 한 번이다. 우연과 구분하지 못하므로 효과라고 말하지 않는다. 표는 다음 행동만 정한다.

## 2. 조건

- graph 조건만 새로 돌린다. 문항 3개(실제 결함)는 같은 증상 문장, 영향 범위 1개는 같은 요청이다. 바뀌는 것은 그래프 도구 문단과 서버 안내문을 더한 것뿐이다(앞 grep 프롬프트와 같은 나머지).
- 그래프는 기준 커밋(모듈 있음)이고 응답하는 래퍼를 샌드박스 안에서 확인했다(네 그래프 모두 응답, 없는 경로는 오류를 낸다).
- 재는 값: 도구 결과 글자 합, Bash 호출 수, 보고 토큰, 출력 토큰, 그래프 도구 호출과 응답 글자 수, 정답(앞과 같은 기준), 명령 검사(허용 밖, git, gh, 네트워크).
- 그래프 호출 중 결과를 받은 호출 수를 기록에서 세고, 빈 응답이면 실패로 적는다.

## 3. 약점

- 프롬프트에 서버 안내문(약 6.7천 자)이 더해져 시작 글자가 늘어난다. 읽은 글자 합에는 넣지 않고 따로 적는다.
- 에이전트가 그래프를 쓸지 말지는 에이전트가 정한다. 안 쓰면 그 문항은 "쓰지 않음"으로 적는다.
- grep 기준값은 앞서 한 번 잰 값이다. 같은 문항을 다시 풀면 크게 달라질 수 있다.
