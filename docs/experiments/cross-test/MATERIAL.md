# 실제 결함 문항의 재료 점검

작성 2026-11-24. [CONCLUSION](./CONCLUSION.md) 뒤 사용자가 추천 A(재료 점검)를 골랐다. 에이전트를 쓰지 않았고 새 측정은 없다. 자료 [data/real-defects-material.json](./data/real-defects-material.json).

## 1. 왜

go-stablenet의 문항은 모델이 수정을 기억할 수 있고, grep 에이전트가 거의 다 풀었다. 다른 세션이 센 팀 코드 결함(모델 지식 기준일 뒤에 작성)이 문항의 재료가 되는지 본다.

## 2. 걸러 낸 과정

| 단계 | 남은 수 |
|---|---|
| 다른 세션이 센 결함 단위(팀 코드, 2026-07-01 이후 작성). 분류 자체는 검토하지 않음 | 29 |
| 제품 코드이고 병합된 PR(열림 2, 닫힘 1, 비제품 2를 뺌) | 24 |
| 로컬 저장소에 수정 커밋과 기준 커밋이 있음 | 24 |
| 두 저장소(go-wemix, go-wbft)와 go-stablenet이 공개 | 3개 저장소 모두 |
| 기준 커밋 그래프가 빌드됨(모듈 누락 0, 로컬 캐시만, 커밋당 약 35초, 340MB) | 24 |
| 수정이 바꾼 기존 최상위 선언이 그래프에 있음 | 20 |
| 앞 시험에서 본 것과 같은 수정(형제 PR 포함)을 뺌 | 17 |

네 개는 정답이 그래프에 하나도 없다(빌드 범위 밖 파일이거나 새로 만든 선언).

## 3. 남은 17개의 모양

- 정답 선언: 1개 9개, 2개 6개, 3개 2개. 파일 2개 이상에 걸친 것은 3개.
- 저장소: go-wemix 16, go-stablenet 1, go-wbft 0.
- 17개 중 정답이 작은 것이 대부분이라 "정답 크기"로 어려움을 만들 수는 없다. 어려움은 증상에서 자리까지의 거리에서 나와야 한다.
- 수정 하나에 여러 hunk가 있고 일부는 선언에 닿지 않는다(임포트, 상수 블록 등). 정답에서 빠진다.

## 4. 남은 일과 위험

- 증상 문장이 없다. 수정을 본 사람이 쓰면 자리를 알려 주기 쉽다(2단계 시험에서 겪음). 수정을 보지 않는 사람이 쓰려면 PR 본문의 문제 설명만 줄 수 있다.
- 공개 PR이지만 결함의 내용에 취약점이 섞일 수 있다. 증상과 정답은 저장소 밖에 둔다.
- 분류와 "팀 코드" 표시는 다른 세션의 에이전트가 붙였다. 확신이 낮다고 표시된 것은 이 17개에서 세지 않았다.
- 앞 시험과 같은 모델로 푸는 한, 모델이 기준 코드를 아는 정도는 그대로다. 줄어드는 것은 수정을 기억할 가능성이다.
