# 실제 결함 5문항으로 grep만 거르기

작성 2026-11-24. 증상 문장과 에이전트를 만들기 전에 고정한다. 재료는 [MATERIAL](./MATERIAL.md). graph 조건은 돌리지 않는다.

## 1. 가를 결정

| 결과 (5문항 중 답에 정답이 하나도 없는 문항 수) | 행동 |
|---|---|
| 0개 | 이 종류의 실제 결함에서도 grep이 충분하다. 이 길을 닫는다 |
| 1개 | 남은 12개에서 grep만 더 거를지 사용자에게 묻는다 |
| 2개 이상 | 17개를 두 조건(grep, 동작하는 graph)으로 푸는 본 시험의 크기와 비용을 제안한다 |

5문항, 반복 1회라 비율을 말하지 않는다. 정답을 일부만 찾은 문항은 따로 적고 위 표에는 넣지 않는다.

## 2. 문항

- 17개를 시드 20261126으로 섞어 앞에서 5개. 순서는 `order.json`(해시 아래). 증상을 쓸 수 없다고 작성자가 답한 것은 다음 순서의 것으로 바꾸고 이유를 적는다.
- **정답:** 수정이 바꾼 기존 최상위 선언(테스트 밖, 기준 커밋 그래프의 선언). 사람이 고르지 않는다. 임포트 등 선언에 닿지 않은 hunk와 새로 만든 선언은 정답이 아니다.
- **증상:** 작성 에이전트는 PR의 제목과 설명 글만 받는다. diff, 소스, 저장소를 보지 않는다. 사용자가 보게 될 현상만 쓰고, 식별자, 파일 이름, 로그 문구, 원인, 고칠 곳을 쓰지 않는다.
  설명 글에 원인이 들어 있으므로 문장이 쉬울 수 있다. 이 시험의 가장 큰 약점이다.
- 문장과 정답은 저장소 밖(`knowledge-data/agent-eval/runs/20261124-real-defects`)에만 둔다. 공개 PR이라도 결함의 내용이 취약점일 수 있다.

## 3. 푸는 조건

- 기준 커밋 트리를 히스토리 없이 격리 폴더에 두고 에이전트 하나가 Bash 읽기 명령만 쓴다. 프롬프트는 [PILOT](./PILOT.md)의 grep 조건과 같고 모델은 이 세션과 같다. 답은 선언 5개까지.
- **채점:** 답 5개 중 정답 선언이 있는지(파일과 이름, 수신자로 찾는다). 정답 재현율, 첫 답이 정답인지도 적는다.
- **검사:** 명령이 허용 폴더 밖을 열었는지, git과 gh와 네트워크를 썼는지 기계로 본다. 추가로 명령에 나온 대문자 낱말 가운데 트리에도 프롬프트에도 없는 것을 세어 기억 흔적을 본다(앞 예비 시험에서 빠뜨린 검사).

## 4. 약점

- 작성 에이전트가 설명 글을 본다. 설명 글에 원인이 있을 수 있다.
- 정답이 1~3개로 작고 파일 1~2개에 모인다. 흩어진 결함은 거의 없다.
- 모델이 기준 코드를 아는 정도는 그대로다.
- 결함을 고른 기준과 "팀 코드" 표시는 다른 세션의 에이전트가 붙였다.
