# 그래프가 LLM에게 도움이 되는지에 대한 중간 결론

작성 2026-11-24. 이 폴더와 [oracle-seed-offline](../oracle-seed-offline/REPORT.md), [log-backtrace](../log-backtrace/REPORT.md), [impact-scope](../impact-scope/REPORT.md)의 결과를 모았다. 새 측정은 없다.
앞선 세션의 21문항 에이전트 평가는 [GRAPH-MCP-AGENT-EVAL](../../research/GRAPH-MCP-AGENT-EVAL-2026-11-20.md)에 있다.

## 1. 확인된 것

- **그래프의 내용은 대체로 맞다.** 필드를 쓰는 곳의 목록은 타입 검사기와 재현율 0.998, 정밀도 0.996(표본 300개)이다. 함수는 재현율 0.933이고, 빠진 곳의 대부분이 패키지 수준 변수의 초기값이다.
- **후보 목록을 넓히는 것으로 이득을 보지 못했다.** 사전 판정선을 넘은 N은 빈자리로 설명됐고, 대조까지 넘은 N은 없다(`RESULT.md`).
- **이번 자료에서 grep 에이전트는 문항을 거의 다 맞혔다.** 위치 찾기 3문항(core 전부), 영향 범위 8문항(F1 0.984~1.000). 앞의 2단계 문항 15개도 core 19개를 모두 찾았다.
- **시험마다 실패하는 자리가 다르다.** 실제 로그 12문항에서는 후보에 정답이 없는 것이 9개였다.

## 2. 확인되지 않은 것

- graph가 에이전트를 돕는지, 돕지 않는지. 두 예비 시험의 graph 조건은 그래프를 쓰지 않았거나(앞 시험), 장비 결함으로 동작하지 않았다(뒤 시험). 동작하는 graph와 grep을 나란히 잰 시험이 없다.
- 토큰을 줄이는지. 응답 크기만 봤고 에이전트의 총 토큰은 재지 않았다.
- 흩어진 큰 정답, 실제 결함, 다른 저장소, 다른 모델. 모든 시험이 go-stablenet과 같은 계열의 모델 하나다.

## 3. 이 자료로 말할 수 있는 범위

- 이 저장소에서 이름이 주어진 위치 찾기와 참조 찾기는 grep 에이전트가 이미 잘한다. 그래프 없이도 정답을 낸다.
- 그래서 같은 종류의 문항으로 graph의 정확도 이득을 보이기는 어렵다. 다음 조건을 하나라도 만족하는 문항이 있어야 차이를 볼 수 있다: grep 에이전트가 틀린다, 또는 읽는 양이 뚜렷하게 다르다.
- 이 결론은 표본이 작고 이미 본 자료로 만든 것이 많다. 일반화하지 않는다.

## 4. 남은 후보 (정하지 않았다)

- 다른 저장소(go-wemix, go-wbft)의 최근 결함에서 만든 문항. 모델 기억이 덜 섞인다. 그래프 빌드와 증상 문장이 필요하다.
- 동작하는 graph와 grep을 같은 문항(4번처럼 흩어진 큰 정답)에서 나란히 재는 시험. 정확도가 아니라 읽은 양과 토큰을 본다.
- 앞선 세션의 과제(증상에서 찾기)에서 첫 검색을 바꾸는 글의 효과 확인(`D22`).

## 5. 추가 (2026-11-24, 실제 결함 5문항 뒤)

- 팀 코드의 최근 결함 5개(모델 지식 기준일 뒤)를 grep 에이전트로 풀었다. 5개 모두 정답을 찾았다([REALDEFECT-RESULT](./REALDEFECT-RESULT.md)). 표본이 작고 증상 문장이 쉬울 수 있다.
- 이로써 위치 찾기 8문항(앞 3, 이번 5)과 영향 범위 8문항, 앞의 2단계 15문항에서 grep 조건은 정답을 거의 다 찾았다. 정확도로 차이를 볼 문항이 남지 않았다.
- 동작하는 graph 조건은 여전히 재지 못했다.

## 6. 마감 (2026-11-24)

- 동작하는 graph를 붙여 4문항을 풀었다. 실제 결함 3문항에서는 에이전트가 그래프를 쓰지 않았고, 영향 범위 1문항에서만 썼다(읽은 양 0.63배, 한 번)([READSIZE-RESULT](./READSIZE-RESULT.md)).
- 사전 표에 따라 이 연구를 마감한다. graph가 정확도를 올린다는 증거는 없고, 읽은 양을 줄인다는 증거는 한 문항뿐이다. 없다는 증거도 아니다.
- 확인된 채 남는 것: 그래프의 내용은 대체로 맞고(필드 사용 목록), 이 저장소와 모델에서는 grep 에이전트가 위치 찾기와 참조 찾기를 거의 다 푼다.
