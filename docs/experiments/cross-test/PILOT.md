## 2. 조건

- **문항:** 1단계 문항 중 blind 출발점이 정답이 아니었고(core가 출발점에 0개) `blind`가 참인 것을 id 순으로 앞 3개. sym-56, sym-58, sym-63.
  graph의 결과를 보고 고르지 않았다. 세 수정은 2026년 2~3월로 모델 지식 기준일(2026년 6월) 전이라 기억이 섞일 수 있다.
- **입력:** 증상 문장 한 개. 이름, 로그, 커밋 정보는 주지 않는다. 소스 트리는 기준 커밋이고 git 기록이 없다.
- **두 조건:** grep(파일 읽기와 검색만), graph(같은 것에 더해 기준 커밋의 그래프 도구). 프롬프트는 도구 문단만 다르다.
- **에이전트:** 세션마다 새로 띄운 general-purpose 에이전트 6개(문항 3 x 조건 2), 반복 1회, 한 번에 같이 띄운다. 모델은 이 세션과 같다.
- **막은 것:** `change_history`, `evidence_for_intent`(과거 PR과 커밋을 보여 준다), git, gh, 네트워크, MCP, 다른 폴더, 하위 에이전트.
- **그래프:** 앞에서 만든 기준 커밋 그래프(모듈 있음). ckg 실행 파일은 `20261124-message-confirm/bin/ckg`이고 호출은 MCP 서버를 한 번씩 여는 래퍼다.

## 3. 통과 조건

- **G1 답:** 6개 에이전트가 모두 정해진 JSON을 준다.
- **G2 세기:** 6개 모두 도구 호출 수와 출력 토큰을 기록에서 셀 수 있다.
- **G3 쓰기:** graph 조건 3개 중 2개 이상이 그래프를 한 번 이상 부른다.
- **G4 새기:** 6개 모두 허용된 폴더 밖을 연 명령이 없고 git, gh, 네트워크를 쓰지 않았다. 명령을 기계로 검사한다.
- **G5 여지:** grep 조건이 3문항 모두에서 core 전부를 찾지는 않는다. 다 찾으면 정확도로 가를 수 없다.

함께 적음: 문항마다 core 중 찾은 수(답 목록 5개 안), 첫 답이 core인지, 호출 수, 출력 토큰, 도구 결과 글자 수. 정답은 `oracle-accepted.json`이고 답을 받은 뒤에 연다.
